# 灵动岛通知

诺米不在桌面时，Nomi 的通知会以「灵动岛」样式出现在屏幕顶部中央：在带刘海的 Mac 上从刘海处展开，在其他屏幕上显示为顶部居中的胶囊。点一下打开对话窗口（提到最前）；按 `Esc` 或点关闭按钮收起整个岛。

等你处理的事（编程助手要权限、沙箱拦下、任务等你批准或验收、Nomi 要你确认的操作）会一直留在岛上，带着按钮，可以直接在岛上允许或拒绝；点某一条（或它的「打开」）会打开对话窗口并跳到它：任务到任务详情，编程助手的请求到它的标签，Nomi 的确认到主对话。

设置：「设置 → 通用 → 通知 / 灵动岛」。

- **启用灵动岛通知**：macOS 上默认开；Windows / Linux 上是可选的顶部胶囊，默认关。关闭后，诺米不在桌面时改用系统通知。
- **通知类型**，可分别开关：等你处理的事（默认开，见下文）、AI 主动消息（主动搭话、每日简报等）、编程助手进度（完成、需要确认或出错时）、日程提醒（到点的提醒与定时任务结果）。
- **始终用顶部胶囊**：不贴刘海，在屏幕顶部居中显示。
- 「预览一条通知」可以先看看效果。

## 通知走哪里

提醒、定时任务结果、主动聊天、编程助手进度和用量预算提醒，每条只出现在一个地方：

- **诺米在桌面上**：只用她的气泡（提醒是提醒卡片），不弹灵动岛，也不发系统通知。
- **诺米关着或隐藏**：用灵动岛；灵动岛关闭、平台不支持或没开这一类来源时，改发系统通知（点击打开对话窗口）。
- **免打扰时段**（「设置 → 知识与记忆 → 日程 → 免打扰」）：什么都不弹，提醒攒到结束时再送。macOS 的专注模式没有公开接口，无法自动感知。
- 编程助手「还有 N 个任务进行中」的定时汇总不会退回成系统通知；定时任务的结果总会写进对话窗口。

## 等你处理的事

在岛上列出、处理完才收起（不管诺米在不在桌面，免打扰时段也显示，因为它们卡着事情往下走）。按 `Esc` 或点列表右上角的关闭可以先收起：这些事没有被处理，对话里、任务页里照样能处理；有新的一条进来时连同它们一起再显示。按钮点了 8 秒没有结果会恢复可点。按钮与对话里、任务页里的是同一个入口，在哪处理都行，处理完各处一起消失：

| 来源                                                     | 岛上的按钮                                                               |
| -------------------------------------------------------- | ------------------------------------------------------------------------ |
| 编程助手要用工具                                         | 允许 / 拒绝                                                              |
| 编程助手的计划等批准                                     | 批准并自动改文件（或「按此方案执行」）/ 逐项确认 / 继续修改              |
| 编程助手被沙箱拦下                                       | 本会话允许 / 始终允许 / 不允许；受保护的文件夹只能不允许或打开设置去处理 |
| 持续任务等批准、预算用完                                 | 批准 / 拒绝                                                              |
| 持续任务配置变了                                         | 已处理，继续 / 放弃                                                      |
| 你接手过的持续任务                                       | 标记完成 / 交回                                                          |
| 持续任务等验收                                           | 通过 / 打开（退回要写意见）                                              |
| 持续任务要核对                                           | 已生效 / 没生效 / 打开                                                   |
| Nomi 要你确认的操作（桌面、命令、MCP、委派交接、文件夹） | 允许 / 拒绝；必须看清楚再定的只给「打开」                                |
| 要补充信息、要重新授权                                   | 打开                                                                     |

「打开」打开对话窗口。任务派出的编程助手标签上的权限请求就是那个任务的「等批准」，只列一次，按任务处理。
已经在列表里的编程助手权限请求，不再额外弹一条「需要确认」的提醒。

只有一条时是一个大胶囊；多条时上面一行「N 项等你处理」，下面逐条列出，最多显示 4 条，再多的在列表里滚动。
有通知进来时叠在列表最上面，几秒后收起。

## 样式

- **带刘海的 Mac**：岛的上沿贴着屏幕最上沿，从刘海里往下长出来，只有下方是圆角；内容（图标、标题、按钮）在刘海下沿下面。刘海版始终是纯黑。
- **没有刘海的屏幕 / 强制胶囊**：深色半透明的悬浮胶囊（宽 440、一条时高 64），四角圆角、投影。
- 左边是 Nomi 的图标（编程助手的事用编程助手的图标），右下角一个角标：进行中转圈、完成绿勾、失败红色感叹号、等你处理琥珀色感叹号、消息粉色爱心。
- 右边：等你处理的是按钮；通知是关闭按钮。
- 窗口高度跟着内容变（页面报给内核，内核改窗口大小），列表变长时窗口长高，不会一直占着一块透明区域挡住下面的点击。
- 展开 / 收起约 0.36 秒，没有回弹；系统开启「减少动态效果」时没有过渡。
- 不抢焦点，在所有桌面空间可见；内容只以纯文本渲染。

## 实现

- `apps/desktop-go/internal/core/island`：通知路由 `notify.go`、等你处理的列表 `pending.go`、版式参数 `geometry.go`（纯函数，有单测）、页面 `island.html`（内嵌进程序）；窗口在 `internal/shell/wailsshell`。
- 等你处理的事从哪来、按钮接到哪：`apps/desktop-go/island_pending.go`（标签事件、任务变化、确认请求出现 / 收起时刷新，另有 5 秒兜底）。编程助手权限请求的详情由编排器记下（`cli/harness/pending_perms.go`）。
- 页面与内核的信号（postMessage）：`nomi:island:size:<高度>` 改窗口高度、`nomi:island:act:{id, action}` 点了按钮、`nomi:island:open` 打开对话、`nomi:island:hidden` 收起完成。
- macOS 上岛窗口是真正的无边框窗口（Wails `MacWindowCornerTypeSquare`）：Wails 默认的 frameless 窗口仍带标题栏样式，系统会把它挪到菜单栏下面并加圆角，刘海模式就和刘海断开了。
- 开发版（`pnpm dev`）的「设置 → 调试」可以在真的岛上看各种样式：每种通知、各来源的「等你处理」样例（一条 / 三条 / 七条滚动等）。样例走 `island.debug`，内核只在设置了 `NOMI_DEV_VIEWS` 时接受；点样例上的按钮只是把它拿掉。
- 是否有刘海按「内建屏 + 菜单栏高度」推断，判断不准时退回胶囊样式。调试：`CD_ISLAND_SIMULATE_NOTCH=1` 可以在任意平台模拟刘海。
