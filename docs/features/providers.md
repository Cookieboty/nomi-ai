# 第三方供应商与模型

入口：设置 →「模型」，或对话区右上角模型选择器旁的按钮。Nomi 对话经本机的统一网关访问第三方供应商（设计见 [unified-gateway.md](../design/unified-gateway.md)）。

## 一键切换

对话区右上角的**模型选择器**（按供应商分组，显示推理 / 视觉 / 上下文长度）、系统托盘的「对话模型」菜单和斜杠命令 `/model` 切换的都是同一个分配，下一次请求立即生效。

## 添加第三方供应商

三步，不用选协议：

1. **选来源**：搜索预设（模型厂商 / 中转平台 / 本地服务，如 DeepSeek、Kimi、智谱 GLM、通义千问、MiniMax、OpenRouter、Amux、Ollama、LM Studio），或「自定义地址」。
2. **填凭据**：可以一次粘贴多个 Key（每行一个，第一个是主 Key，其余按顺序作为备用）。自定义地址贴根地址、`/v1` 或完整的 `/v1/chat/completions` 都可以。服务不提供模型列表时，填一个「测试用模型」。
3. **检测并选模型**：Nomi 并行检测 Anthropic、Responses、Chat、Gemini 四种协议，逐条显示结果和失败原因；至少一种可用才能保存。拉到的模型默认启用预设推荐的那些，向量 / 语音等不能对话的模型列出来但不启用。

本机或局域网地址（Ollama、自建服务）要先确认才会被访问：本地服务预设自动确认，自定义地址会弹窗询问。

## 按任务分配模型

「分配」里可以让 **Nomi 对话**、**工具调用**、**摘要** 分别使用不同的模型；工具调用和摘要默认「跟随对话」。

## 多 Key 自动切换

每个供应商可以有一个主 Key 和多个备用 Key。主 Key 遇到鉴权失败、限流或额度用尽时自动切换到下一个；界面只显示掩码。

## 编辑供应商

点供应商这一行打开详情：

- **Key**：上下调整顺序就是回退顺序；可以停用、改名、删除，一次粘贴多个新 Key；每个 Key 显示最近一次错误（鉴权失败、被限流），恢复后自动消失。
- **模型**：勾选启用，手动添加模型 id，「刷新」重新拉取模型列表（新模型默认不启用）。
- **回退链**：这个供应商出错时依次改用的其它模型。
- **高级**：各协议的地址（留空即关闭该协议）、给某个模型或 Key 限定协议、模型映射、自定义请求头和 User-Agent、清除自动学到的状态；每个 Key 还可以设**并发上限**和**每分钟请求数**（留空 = 不限，超出时请求排队，流式请求排队期间会收到保活）。新建供应商的对话框里没有这两项，保存后在详情里设。

## 模型参数自动适配

网关按内置的模型目录（来自 models.dev，MIT 许可）和模型族规则，把请求调整成上游模型能接受的样子，并在「模型质量 → 请求明细」里给这条请求记一条修正备注：

- 思考深度超出模型支持的档位时降到最近的一档；只给预算的模型按比例换算成预算。
- 推理内容要不要回传、`max_tokens` 与 `max_completion_tokens`、不支持的采样参数，按模型自动处理；目录里标为不支持图片的模型，图片换成一行说明。
- 上游明确拒绝某个参数或档位时，换一种写法只重试一次，并记住结论（7 天，目录更新后重新判断）。
- **严格模式**（「模型」页「显示协议」旁的开关，默认关）：打开后模型不支持的参数直接报错，而不是悄悄丢掉，适合排查参数为什么没生效。

## 终端启动命令

「模型」页底部的开关（默认关）。打开后在 `~/.nomi/bin/` 生成 `nomi-claude`、`nomi-codex`、`nomi-gemini`、`nomi-grok`、`nomi-dsh`：在终端里运行它们就用「模型」页给这个 CLI 分配的第三方模型，`--nomi-model 供应商/模型` 可以临时换模型；直接运行 `claude`、`codex` 仍是官方登录。Nomi 没在运行时会提示先打开 Nomi。加入 PATH 前会先确认，只在 shell 配置文件里加一段带标记的内容，关闭开关时删除。

## 模型质量

设置 →「模型质量」（在「模型」页旁边）持续记录每次请求的质量，用来比较供应商、模型和 Key（设计见 [model-quality](../design/model-quality.md)）。

- **两种测量口径**，界面上分开看：
  - **网关层**：经 Nomi 网关的请求（Nomi 对话、编程助手用第三方供应商），按 HTTP 请求计，有首字节、Key、每次尝试与回退。
  - **CLI 层**：在 Nomi 里运行的编程助手（官方账号和第三方都有），按每一轮计，时间包含 CLI 自身和工具执行的开销。官方账号只有这一层；第三方两层都有，所以可以在 CLI 层对比同一个编程助手用官方账号和用第三方供应商。终端里直接运行的 CLI 不在 Nomi 里，统计不到。
- **指标**：请求数、成功率、失败率（按原因分：鉴权、限流、上游 5xx、首字超时、断流、空闲超时等）、取消率（首字前 / 输出中）、断流率、回退率、缓存命中率（按 token / 按请求）、TTFB、TTFT、TPOT、E2E、输出 tok/s，延迟给 p50 / p90 / p99。上游缓冲后一次吐出整段的请求标为「整段吐出」，不计入 TPOT 和 tok/s。
- **默认口径**：取消不计入成功率的分母；400、上下文超长这类「请求本身的问题」不算供应商失败。两项都可以切换。看供应商和 Key 时可以「按尝试」计数：回退前失败的 Key 会记一次失败。
- **四个标签**：总览（指标卡与上一周期对比、失败原因、按供应商）、对比（按供应商 / Key / 模型 / 模型族 / 客户端 / 来源 / 协议 / 解析方式分组，勾选 2～4 项并排，快捷对比「同一模型跨供应商」「同一供应商跨 Key」「本周 vs 上周」）、趋势（按小时 / 天）、请求明细（原用量面板的「最近请求」：每条的结果、时间线、各次尝试、网关修正、来自哪个标签、模型怎么选出来的、诊断追踪 id）。任何数字都可以点进请求明细；对比表和请求明细可以导出 CSV。
- **存储**：只存元数据（时间、状态、token、模型名、供应商与 Key 的 id），不含对话内容；按天写在 `userData/usage/quality/`，默认保留 30 天（可选 7 / 30 / 90），受「用量与费用」的总开关控制，可一键清空。

打开「设置 → 隐私与权限 → 诊断日志」后，网关会把请求和响应正文脱敏后存到 `userData/gateway/trace/`，24 小时后自动删除（见 [隐私与安全](privacy-security.md#诊断日志)）。

## 安全

- API Key 用系统安全存储加密（macOS 钥匙串 / Windows DPAPI / Linux libsecret·kwallet），保存在本机 `gateway/store.json`（权限 0600）。
- 保存后界面只能拿到掩码；Key 只在主进程和网关进程的内存里解密，只随请求发往你为该供应商配置的地址，不上报、不同步。
- 网关只监听本机，每个客户端用自己的令牌访问。
- 工具结果会发给谁按真正的上游判断：经网关访问云端供应商时按云端处理（隐私设置里的「仅本地」与云端同意照常生效）。

## 升级与兼容

- 首次启动新版本时，原有的 Nomi 供应商（`ai-providers.json`）和编程助手的第三方供应商自动迁移进网关，原文件不改动；旧配置里的本机地址视为已确认。
- 环境变量提供的供应商（如 `DEEPSEEK_API_KEY`、`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`GEMINI_API_KEY`、`OLLAMA_BASE_URL`）暂时还不在「模型」页里：「模型」页没有为 Nomi 对话分配模型时由它们提供，`/model` 里也能选。`NOMI_PROVIDER=<id>` 可强制指定供应商（此时右上角的选择器锁定）。
- 服务商图标来自 `@lobehub/icons-static-svg`（MIT），仅用于标识对应服务；没有图标时显示首字母头像。

## Claude Code / Codex / Gemini / Grok / dsh 用第三方模型

- 每个编程助手标签在对话区右上角选来源：「官方账号」（CLI 自己的官方登录，见下文「多个官方账号」）或「第三方」（「模型」页里的任意模型，经 Nomi 网关自动转换协议）。只影响这一个标签，同一个 CLI 可以一个标签用官方、另一个标签用第三方。
- 「模型」页的「编程助手」一栏给每个 CLI 设选「第三方」时默认用的模型（Claude Code 还可以展开「各档模型」分别设 Opus / Sonnet / Haiku / Fable 各档和子代理模型；Haiku 档就是 Claude Code 跑后台任务——起标题、摘要等——用的快速模型）以及新标签默认用哪种来源。
- 第三方只作用于 Nomi 启动的那个 CLI 进程：不写 `~/.claude/settings.json`、`~/.codex/config.toml`、`~/.grok`、`~/.gemini`、dsh 的配置，也不碰官方凭据；终端里直接运行的 CLI 永远是你自己的配置和官方登录。会话历史照常写进各 CLI 自己的目录，和官方会话一起显示。
- 改默认官方账号只影响跟随默认账号的官方标签。第三方标签换回官方时，第三方的推理内容不能发给官方接口，会用带上下文的新会话继续，原会话保留。
- 启动第三方会话时 Nomi 会告诉 CLI 模型的真实上下文窗口和输出上限，避免过早压缩或超长报错；模型不支持图片时图片会换成一行说明，不让整个请求失败。
- **辅助模型**：CLI 起标题、写摘要、给下一句提示这类辅助请求用的模型。「模型」页每个 CLI 都可以单独选（Claude Code 在「各档模型」里，其它在「更多」里）；不设就跟主模型一样。
- **按标签换模型**：标签输入栏的模型按钮换的是这一个标签的模型。Nomi 按 CLI 的能力选最省事的方式：Grok 只改网关里这个标签的绑定，进程不重启；Codex 和 Claude（档位模型不随之变化时）在原进程里切换；Gemini、dsh 以及档位跟随主模型的 Claude 重启进程并续接同一个会话。
- **标签令牌**：每个第三方标签的 CLI 进程用自己的一次性令牌访问网关（`nomi-tab-` 开头，只在这个进程的环境变量里，网关只存哈希）。网关据此知道请求来自哪个标签、用哪个模型；进程退出或标签关闭后令牌立即作废。官方标签从不带令牌。
- 旧版本写进 CLI 全局配置的第三方设置会在升级后自动撤销一次（先备份到 `userData/gateway/backups`，只删 Nomi 写入的值，你自己改过的不动）。

「编程助手」页每个 CLI 仍有「版本」卡片（检查并一键安装 / 更新）和官方账号管理。

## 多个官方账号

Claude Code、Codex、Grok、Gemini 都可以登录多个官方账号，并且**同时**使用：

- **一个账号一个配置目录**：每个账号是 CLI 自己的一个配置目录（Claude `CLAUDE_CONFIG_DIR`、Codex `CODEX_HOME`、Grok `GROK_HOME`、Gemini `GEMINI_CLI_HOME`），这是各 CLI 官方支持的多账号用法。登录在这个目录里由 CLI 自己完成（浏览器授权或设备码），**Nomi 不读取、不保存、不转发任何官方凭据或令牌**（Anthropic 的使用政策要求登录必须走官方流程，第三方不得收集或中转 Claude 账号凭据）。
- **本机登录**：你自己在终端里登录的那个（`~/.claude` 等）始终在列表里，叫「本机登录」，不会被 Nomi 改动。终端里直接运行的 CLI 永远用它。
- **默认账号**：新的官方标签用默认账号。改默认账号只重启跟随默认的官方标签，单独指定了账号的标签和第三方标签不受影响；不再改写全局登录。
- **按标签选账号**：在标签的模型按钮里可以给这个标签指定账号，同一个 CLI 可以两个标签分别用两个账号并行。换账号只重启这一个标签的进程，会话照常续接。
- **会话、技能、配置共享**：账号目录里的会话历史、项目信任、MCP 服务器、技能、命令等软链回你自己的 CLI 目录（Windows 用目录联接），所以所有账号看到同一份历史；生成的配置会去掉指向第三方的地址和密钥，账号目录里只会用官方登录。
- **历史标注**：Nomi 记下自己启动的会话用的是哪个账号（只记会话 id → 账号，不含凭据）。同一 CLI 有多个账号时，历史列表会标出账号；从历史打开时按原账号续接。
- **在终端里用某个账号**：账号卡片上可以复制一条命令（设好配置目录变量再运行 CLI），在自己的终端里用这个账号。
- **额度**：订阅额度显示的是默认账号的。Nomi 先读 CLI 已有的数据；读不到时才在默认账号的目录里运行一次官方 CLI 去取（手动刷新 60 秒内最多一次；后台只在额度卡打开、最近 24 小时用过该工具时，每个工具至少隔 30 分钟取一次）。「主动刷新额度」关闭时从不运行 CLI。
- **删除账号**：本机登录不能删；有标签正在用的账号不能删。删除时先在账号目录里运行 CLI 自己的登出，再删除目录（以及 macOS 钥匙串里这个目录对应的条目）。
- **从旧版本升级**：旧版本把账号凭据加密存在 Nomi 里并切换全局登录。升级后这些凭据和备份会立即删除，账号保留为「需要重新登录」，点「登录」在它自己的目录里重新登录一次即可。

## 外部 CLI（ACP）

「设置 → 编程助手 → 外部 CLI」可以接入任意支持 [ACP（Agent Client Protocol）](https://agentclientprotocol.com) 的编程助手，不需要 Nomi 内置它：

- **添加**：填名称、命令（可执行文件的绝对路径或 PATH 里的名字）、参数（每行一个）和需要的环境变量名。参数里可以用 `{cwd}`（标签的工作目录）和 `{home}`（主目录）两个占位符，其它写法原样传给 CLI。
- **测试**：只做一次 ACP `initialize` 握手，显示 CLI 报告的名称、版本、是否支持续接与图片；不建会话、不发消息，在临时目录里运行。
- **使用**：点「新建标签」开一个这个 CLI 的标签，像内置编程助手一样对话；进程回收或重启后用 ACP `session/load` 接着同一个会话（CLI 支持时）。
- **删除**：用它的标签保留，但不能再发消息；重新添加同一个 id 即可恢复。

信任模型（L1 声明式插件，设计见 [cli-plugin-architecture §5.9](../design/cli-plugin-architecture.md)）：

- 只保存命令、参数模板和**环境变量的名字**（`userData/cli-plugins/external/<id>.json`，权限 0600），从不保存变量的值或任何凭据；值从启动 Nomi 的环境里继承，缺少时启动前提示。
- 不加载任何第三方代码：命令直接启动，**不经 shell**，参数只做占位符替换，不会展开变量、通配符或命令替换。
- 外部 CLI 以你的身份在你的电脑上运行，只添加你信任的程序。
- 权限只有「逐项确认」：每次工具调用都通过 ACP 的权限请求由你在 Nomi 里批准；Nomi 不替它切换模式。
- 外部 CLI 不接 Nomi 的官方账号、第三方模型（网关）、订阅额度和进度监视——这些需要按 CLI 写代码，只给内置编程助手。登录请在终端里用它自己的命令完成。
- id 不能与内置编程助手重名；清单校验不过的文件会标为「清单无效」，不影响其它 CLI。
