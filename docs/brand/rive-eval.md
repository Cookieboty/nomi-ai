# Rive pipeline evaluation (Nomi · 诺米)

> Status: **adopted for the 2D mascot path** on the high-fidelity branch. The shipped renderer now uses the
> `nomi-complete.riv` scene by default for built-in sprite characters; `?rive=full` selects the full-body artboard.
> Evaluated headless on a Linux box (no GPU, no login) on 2026‑10‑16.

Question: can a Rive pipeline (AI art → SVG → Rive CLI) give the 2D mascot clearly better and more varied animation
than the layered-sprite rig, **without touching the brand lock** (docs/BRAND.md, `brand-lock.json`)?

**Short answer: partial adopt.** Rive is a good _player and rigging format_ for the body/arm motion (native bones, mesh
skinning, easing, a state machine, one `.riv` file). It does **not** by itself make the animation better — the limit is
the flat, single-piece art. The "AI → SVG" step is a **drop**: it destroys line-art detail and is the one thing that
makes Rive lag. Brand parts must stay the locked rasters.

## 2. PoC scene (`rive/nomi-poc`, `.riv` at `packages/renderer/public/assets/models/rive/nomi-poc.riv`, 2.4 MB)

Generated by `python3 scripts/rive-eval/build-nomi-rive.py` (≈900 lines) — it reads the real manifest rig geometry and the
**existing `ACTIONS` library** (`scripts/rive-eval/export-actions.mts` dumps the 43 actions as JSON), so the PoC is also a
migration test for the whole action set.

- **Art**: only the locked master layer PNGs, embedded verbatim (`ImageAsset`). 29 layers; every embedded PNG is
  byte-identical to a `brand-lock.json` entry (enforced by `tests/mascot/rive.test.ts`). Nothing is redrawn or traced.
- **Rig**: nested wrapper nodes (idle ▸ action) so idle and action compose; both arms are **3-bone skinned meshes**
  (shoulder/elbow/wrist, weight blend at the elbow) that reproduce what `meshArm.ts` does by hand; hands are swapped with a
  `Solo`; mouths with a `Solo`; the prayer-hands piece is cropped with a `ClippingShape`; sparkle FX are star shapes.
- **Idle layers** (always on, different lengths so they never lock-step): breathing + weight shift, hair/ribbon sway,
  gaze wander, blink loop (incl. double blink), badge/strap swing.
- **Actions (8, one `LinearAnimation` each)**: wave, hello, nod, think, pray, cheer, thumbs_up, celebrate.
- **State machine `Nomi`**: idle layer + one layer per action, entered by view-model **triggers** with the same names
  (`vmi.trigger('wave').trigger()` in the web runtime, `--data=wave=1` in the CLI), auto-return to idle.
- `rive rive/nomi-poc --verify` → 0 errors / 0 warnings; `inspect --summary` clean.

Screenshots (CLI renders, frames 0/20/40/60/80/110/140/170): `docs/brand/rive-eval/sheet-*.jpg`; full-size sheets and
frames on the box under `/workspace/screenshots/nomi-rive-eval/r2/`. Side by side with the current canvas rig:
`docs/brand/rive-eval/compare-wave.jpg` (top row canvas rig, bottom Rive). **Same art, same poses** — the Rive wave is
roughly equal to the existing wave, not better. Web runtime renders (canvas-lite / canvas / webgl2) match the CLI.

Known gaps in the PoC (all fixable, none blocking): dark seam at the shoulder when the arm is raised, no plug fill at the
stump, no iris clipping, blink is a `scaleY` squash of the eye layers (the canvas rig draws procedural skin lids; the
brand-lock rule is "rigid transforms only", so this must be redone with lid art or opacity before any adoption), no brow /
blush / mood‑FX.

**Action coverage of the existing library**: the exporter handles 25 of the 38 animation params; **15 of 43** actions convert
completely today. The remaining 28 only miss `brow` (16 actions), `blush` (7), `shoulder` (4) and the procedural FX
(`fxHeart/Sweat/Blush/Question/Exclaim/Gloom/Tear/Anger/Zzz/Note`) — i.e. they need brow/blush overlay art and FX shapes,
not a better player.

## 3. SVG route (non-brand part only: `layers/hands/hand-wave.png`, 285×675)

`scripts/rive-eval/svg/trace.py` (vtracer, colour, stacked, spline) → SVG → rendered back and diffed against the PNG;
`svg2rml.py` converts to `<Shape><PointsPath>` with `CubicDetachedVertex` and Rive renders it (`--verify` ok).

| preset   | paths | bezier segments | control points | SVG size | MAE (RGB, on flat bg) | alpha IoU |
| -------- | ----- | --------------- | -------------- | -------- | --------------------- | --------- |
| fine     | 473   | 4 970           | 14 908         | 174 KB   | 5.5                   | 0.960     |
| medium   | 150   | 1 982           | 5 944          | 70 KB    | 5.5                   | 0.962     |
| coarse   | 31    | 666             | 1 998          | 23 KB    | 6.7                   | 0.964     |
| x‑coarse | 4     | 139             | 417            | 5 KB     | 8.7                   | 0.967     |

- **Fidelity is poor.** Even at 15 k control points the palm lines, finger creases and the dark outline are lost or turn
  into blotchy fragments, and edges get a halo (alpha IoU never exceeds 0.97). At the point counts that are cheap enough
  to animate, the hand becomes a flat beige silhouette (`docs/brand/rive-eval/svg-vtracer-vs-raster.jpg`). This art is
  painted/line-art, not flat vector art; auto-tracing is the wrong tool for it. A silhouette-only trace is fine for a shadow
  or a hit-area, not for the visible hand.
- **Runtime cost (6 copies of the hand rotating, 480×560 canvas, software GL, `@rive-app/canvas`)** — main-thread ms/frame
  and fps: raster 0.40 ms / 60 fps · x‑coarse 0.46 / 58 · coarse 1.27 / 30 · medium 5.9 / 15 · fine 16.9 / 7 (webgl2 runtime on
  software GL: 2.8 fps). Vector cost scales with points; a raster mesh costs the same however detailed the art is. "Dense
  points lag" is confirmed — and the detail level you would need for fidelity is exactly the level that lags.
- **RML can embed paths** (`PointsPath` + cubic vertices) but cannot import an SVG file; the converter above is ~60 lines.
- **Brand**: tracing/AI-SVG is not allowed for face, clip, N logo, badge, jacket, hairband, choker. For non-brand parts it
  is not worth it either (hands/sleeves are shaded art). Recommendation: **drop the SVG step**; keep rasters (optionally on
  a bone-weighted mesh, which Rive does well).

## 5. Honest comparison with the current rig

|                               | current layered canvas rig                                                             | Rive PoC                                                                                                                                                                                                                                                  |
| ----------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| motion quality (same art)     | good already (43 actions, procedural lids, brows, FX, foreshortening)                  | **equal at best**; smooth easing/elastic, mesh bend at the elbow is nice, but nothing the canvas rig can't do                                                                                                                                             |
| why it still looks "mediocre" | flat single-piece layers: torso/jacket/hair are rigid slabs, arms are one sleeve piece | **unchanged** — the player is not the limit, the art decomposition is                                                                                                                                                                                     |
| effort to add an action       | edit a track table in `actions.ts` (typed, unit-tested, brand-lock tested every frame) | author keyframes in RML/editor + state-machine layer; needs the exporter to keep the 43 existing ones in sync                                                                                                                                             |
| effort to get _better_ motion | add layers (split hair, torso, hands, lids) — art work                                 | same art work, but Rive then gives bones, mesh, constraints, nested state machines & an editor/preview for animators                                                                                                                                      |
| brand safety                  | per-frame rigid-transform test, sha-locked layers                                      | rasters embedded verbatim and byte-tested; but mesh deformation / squash is _possible_ and the per-frame "rigid only" guarantee is not enforceable in the `.riv`                                                                                          |
| perf                          | 0.4–2 ms/frame canvas                                                                  | ≤ 1.1 ms/frame; +772 KB wasm (gz 322 KB) +200 KB js, 2.4 MB `.riv`                                                                                                                                                                                        |
| tooling risk                  | in-repo TS, fully tested                                                               | external closed CLI 1.6.0 (no SVG import, CLI quirks, scripts need login/publish), wasm needs CSP loosening, no physics (hair jiggle = keyed loops), second animation system to maintain, expression/lip-sync would need a data-bound rewrite of the face |

## 6. Recommendation: **partial adopt (only if the art is decomposed), otherwise drop**

1. **Drop AI→SVG→Rive** for this character: fidelity is bad at usable point counts, and dense paths are what lag.
2. Rive alone does not fix "mediocre": the same rigid layers look the same in any player. The lever is **more layered art**
   (hair strands/bangs as separate meshes, torso/jacket split with a bendable waist, forearm+hand variants, eyelids/brows
   as layers) — worth doing **first, in the existing rig**, where the brand tests already guard it.
3. If, after that, richer secondary motion is wanted (cloth/hair on bone-weighted meshes, IK, blended state machines, an
   animator-facing editor), Rive is a reasonable target: keep brand rasters embedded verbatim (test included), use Rive for
   body/arm/hair meshes and the state machine, keep face expression/lip-sync data-bound.
4. Before that: decide the CSP question (`'wasm-unsafe-eval'`) and pin the CLI version.

Suggested next steps: (a) split hair/torso/hand art (non-brand re-cuts only, brand layers untouched); (b) finish the exporter
(brow/blush/FX, 28 remaining actions) and add lid art for the blink; (c) data-bind expression/mouth/look to the Rive view
model and re-measure on real GPU hardware; (d) maintainers decide on CSP; (e) run a short A/B with the user on 3–4 actions.

## Reproduce

```bash
curl -fsSL https://releases.rive.app/cli/install.sh -o /tmp/rive-install.sh && bash /tmp/rive-install.sh
sudo apt-get install -y libegl1 libgles2          # headless libs
python3 scripts/rive-eval/build-nomi-rive.py      # → rive/nomi-poc/{rive.yaml,scene.rml}
~/.rive/bin/rive rive/nomi-poc --verify           # 0 errors
~/.rive/bin/rive rive/nomi-poc --once             # → rive/nomi-poc/build/nomi-poc.riv (copy to public/assets/models/rive/)
python3 scripts/rive-eval/shots.py /tmp/shots     # contact sheets via the CLI
python3 scripts/rive-eval/svg/trace.py            # vtracer stats/diff (needs vtracer, svgpathtools, cairosvg)
# in the app (vite dev): open /?rive=1   or   localStorage.setItem('nomi.experimental.rive','1')
```

`scripts/rive-eval/harness/` holds the playwright harness used for the web‑runtime/CSP/perf runs (paths are box-specific).
