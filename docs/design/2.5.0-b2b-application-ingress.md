# 2.5.0 B2b：实际主对话入口与租约 actor

## 交付边界

这是 **S1 持久化的真实应用接线**，不是另一个平行 fake store，也不是 2.5.0 全功能完成。扩展原 convstore 的决定不变；不引入新的权威日志或双写。B2a 文档是当时快照，本记录更新应用调用关系。

- 应用启动现在安装 leased Session registry 和 typed IPC；已显式采用 managed 模式的主聊天发送会真正走它。
- 生产注册的唯一 factory 是 **实验性 API 纯文本适配**。实际 API facade / provider / persona-workspace-network preparation 可执行，但本轮只用 fake provider 验证，没有调用真实模型。
- **没有注册官方 Claude/Codex 驱动，没有首用选择/迁移界面，没有让未配置 provider 的用户直接用本地 CLI 聊天。** Claude→Codex→Claude 的本轮证据来自通过真实 IPC 的 fake Runtime，不能当作真实 CLI 已可用。
- 未管理的旧 API 会话保持原工具循环与读写行为，不自动迁移。实验性 managed API 尚无工具/记忆/知识库/skills 桥接能力，不能宣称完全替代旧 API agentStream。

## 已连接的生产路径

1. `shellhandlers.Install` 用同一个 convstore 创建 `core/mainchat.Registry` 并挂 `conversation_runtime.go`；`main.go` 向 registry 注册 `airouter.ManagedTextTarget`，退出时 Close。
2. `runtimeCapabilities` 只报告可用 factory；`runtimeAdopt(id, backend, confirm:true)` 在迁移前验证 factory、identity 与权限能力。不存在的 driver、未确认请求和 Windows 写入 gate 都不触碰旧正文。
3. Registry 懒取得 convstore OS lease，一 lease 一 Session；窗口 IPC 结束不等于取消已接受的后台 actor。状态读取只恢复持久 checkpoint，不启动模型。
4. `runtimeSend` 必须带观察到的 generation；Session 在同一锁内检查并保存 user revision / attempt / generation，再恢复 target、规划 bounded handoff、保存 dispatch checkpoint，最后调用 Runtime.Start。绑定按 account/cwd/config 等完整 compatibility 匹配，不能靠替换当前 factory 偷换旧 native identity。
5. `useChatSends` 的普通/流式主入口优先走 `IPCClient.sendManagedConversation`；服务只读 `conversations.messages` 权威投影及 runtime draft，不执行旧 `user.early()`、assistant save、harness tab send、自动标题或 memory/compaction 链。
6. 旧 `ai.chat.sendMessage/stream/agentStream/regenerate` 根据 product conversation ID 拒绝 managed ID；普通旧发送也固定携带起始 conversation ID。旧 append/put/replace/import 继续被 convstore 拒绝，视图不能成为第二作者。

新契约均限 chat surface。adopt/select/send/approve/edit 标记危险操作；审批仅转发显式 allow/deny 决定，不生成任何自动许可。

## 生命周期与真实状态

- 同一 product conversation ID、sidebar metadata 和全部旧附件/未知字段始终由原 Store 投影。new API 消息也有持久 timestamp。
- runtimeChanged 只在 Session 接受事件或进入明确 uncertainty 时发布；旧 token、取消 generation、错误 native/plan/revision 的 ACK 不会经 observer 写入正文、coverage 或审批。
- UI 在 admission response 前订阅并缓存事件，按 attempt/generation 过滤。terminal 不被晚到 running 覆盖；观察超时也覆盖 pending admission，绝不自动重发。
- turn-specific cancel 带原始 generation，连“停止先于 send 到达”也持久 fence。无法证明停止时保留 uncertain，不自动 retry。
- Release/Close 取消 actor context，持久化未完成工作的 uncertainty，再释放 lease；旧 callback 仍被 fencing。恢复时 generation 增长，旧 IPC 不可重新执行。
- 删除在 Session admission 锁内验证 idle，并在**同一个权威 envelope** 原子提交 tombstone + checkpoint；保留历史与 legacy archive，不删除其他文件。busy delete 不自动排队重试，视图恢复 sidebar。多个 tombstone 不移动其他对话的 identity/count/preview。
- `Deleted:false` 在 JSON 中省略，保留读取 B2a 既有 checksum 的兼容性。单写者与 B2a 故障注入/迁移验证保持有效。

`runtimeSelect` 当前是 idle-only 的“为下一次 send 选择 target”操作；恢复和 full/delta handoff 在 send 中执行，旧 binding 不被覆盖。**完整保存源→准备目标→恢复→交付→提交/回滚的生产 switch 协调器仍未交付**，不能把这个元数据选择器说成完整 cross-CLI switch 事务。

## API 适配的保守降级

`airouter/managed_text.go` 复用真实 `Chat.Stream`，不调用 `AgentStream`，不套 CLI 工具循环。权限仅 `deny`；不广告 attachments/native approvals/native resume。每次 API 执行明确 new/stateless → full，不冒充 native resumed。

只有非空实际 delta 或成功返回的完整空回复才报告 delivery；error chunk（包括 Go 返回 nil 的 error chunk）和空进度后报错绝不提升 coverage。部分文本后失败仍是 unknown/uncertain，而非可自动重发。Cancel 等待本进程运行确实结束；重启丢失运行句柄时返回 unknown。运行句柄仅保留当前 attempt，不无限增长。

附件、rewind override、知识库桥接、后台转交和 view 元数据/正文编辑目前明确拒绝。审批/恢复/选择 IPC 已接，但完整控制界面、重启 draft 展示、managed rename 和 API 工具能力对齐尚待后续实现。

## Windows 与兼容性

`convstore.ManagedSupported()` 在 Windows 为 false；capabilities 无可用 managed backend，adopt 在任何迁移前返回 unavailable。未管理的旧 API chat 仍可发送/编辑；旧/managed 历史投影仍可读。没有跨平台自动迁移，也不把 fail-closed 耐久写入当作可生产采用的实现。

本轮验证 Linux；**未跑 Windows/macOS native runner**。最终 2.5.0 仍须实现并原生验证 Windows 耐久替换/flush/lease 故障路径，而不是永久以 gate 冒充完成。

## 验证与环境

- 通过真实 contract Router 的 fake-runtime ingress：同一 sidebar 的 Claude→Codex→Claude full/full/delta、原 native resume、当前请求一次、7 条权威消息的逐字重载、account/cwd/config 不兼容拒绝。
- 真并发 IPC admission 只执行一次；release/admission race、跨 registry lease、恢复中退出不死锁、停止先到、busy delete、审批、取消后晚 ACK、重启 unknown 无重放、多个 tombstone 投影。
- 真实 API facade + fake provider：成功/空回复/error chunk/空进度后 error/partial error、无工具循环、取消证明与重启 unknown、managed legacy 入口拒绝，旧 API 入口仍可执行。
- typed TS 传输与实际 React send hooks：早到完成、取消、stale/foreign 事件、超时不重试、不重复 view 保存、不支持能力拒绝；视图已知/迟到 ownership 以及 busy delete 的回滚投影。
- 完整 conversationruntime/convstore/shellhandlers/airouter/contract/archguard 测试及三次 shuffled race，既有 B1/B2a 回归不减项；完整 ai-chat、contract 与 root 套件另记执行数量。

环境修复不改测试门槛：保留所有共享依赖与其他 worktree，只把本 checkout 的 workspace package links 指回自身，避免 repo-paths 误读 2.4.2 的资产。正常初始化 LFS filters，保留原 Husky wrapper 与既有 LFS pre-push 委派，仅下载/检出本分支干净的官方 Rive 文件。Markdown parser 两个现有推断返回值显式命名原 `unist.Node` 类型，修复链接依赖的 TS2883，不改变运行行为或削弱类型。
