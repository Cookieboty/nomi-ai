## 2. CLI 发图能力矩阵

| 后端        | 路径                        | 是否支持发图 | Nomi 采用的文档化注入方式                                                                                 | 不支持时 UX                                                                |
| ----------- | --------------------------- | ------------ | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Claude Code | 常驻 `stream-json` stdin    | ✅           | `user.message.content` 为 Anthropic content blocks：`text` + `image.source={type:base64,media_type,data}` | —                                                                          |
| Codex       | `app-server` `turn/start`   | ✅           | `input: [{type:'text',...}, {type:'localImage', path}]`（官方协议；读本地文件，禁远程 http）              | —                                                                          |
| Codex       | `exec --json` 回退          | ✅           | 每个附件 `--image <absPath>`（官方 CLI）                                                                  | —                                                                          |
| Grok        | ACP `session/prompt`        | ✅           | `prompt: [{type:'text',...}, {type:'image', mimeType, data}]`（ACP ImageContent）                         | —                                                                          |
| Grok        | `grok -p` 回退              | ✅           | 落盘后用 `--prompt-json` 传含 image 的多模态 JSON（官方 headless 文档）                                   | —                                                                          |
| Gemini      | ACP（与 Grok 同套）         | ✅           | 同 ACP image content block                                                                                | —                                                                          |
| dsh         | `--profile headless --json` | ❌           | **无**已文档化的无头图片参数 / stdin 块                                                                   | 输入区明确提示「dsh 暂不支持图片」；**禁止静默丢图**；发送时拦截并还原附件 |
| Nomi        | 原生对话                    | ✅（已有）   | 现有 vision 路径，本需求不改                                                                              | —                                                                          |

约束：

- 格式：`png` / `jpg|jpeg` / `webp` / `gif`；沿用现有 `MAX_ATTACHMENTS` 与体积上限。
- 主进程只接收 base64 + mime；Codex / 需要路径的端写入会话临时目录（可清理），不读用户无关目录。
- 会话气泡存 **缩略图**（data URL 或已有 `chat-asset://`），不把全尺寸 base64 永久塞进 messages JSON。
- 带图消息**不入队**（与现 MessageInput 一致）：忙时提示等本轮结束。

## 3. Codex Desktop 交互参考（只借鉴设计，不复制代码）

对照公开产品体验（非源码）：

1. **输入区**：缩略图横条可移除；不支持的模型 / 端有黄条提示。
2. **上下文**：输入区附近迷你进度条（已用 / 窗口），点开或 `/context` 看分类。
3. **Changes**：侧栏或底部「Changes」列出本会话工具改过的文件（路径、+/-、状态）；点条目看 diff / 预览。
4. **Git**：只读工作区 status + 行级 diff 着色；与 Changes 可同面板分 Tab（「本轮产物」/「工作区」）。

Nomi 落点：

- 迷你条：挂在 composer 上方（`ContextUsageBar`），复用 `estimateContext` / `contextWindowFor`。
- Changes + Git：会话底部可折叠面板 `SessionChangesPanel`（Tabs：`本轮变更` | `工作区 Git`），diff 复用已有 `DiffView` + `diffsOf`；Git 复用 `harnessClient.gitDiff`（只读）。

## 5. 非目标 / 取舍

- 不做 CLI 写操作（commit / push / reset），除非用户后续明确要求。
- 不解析用户家目录下任意文件为「产物」；只认 tool trace 与会话 cwd 的 git。
- dsh 发图等官方文档出现前保持明确不支持。
- Grok ACP `initialize.promptCapabilities.image` 可能仍报 false，但协议与实测接受 ImageContent——按文档化 ACP 块发送；若某版本拒绝，错误原文回显，不静默丢图。
- 不复制 Codex Desktop 源码或私有资源。
