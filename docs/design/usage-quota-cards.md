# 订阅额度卡片设计（调研 + 落地）

状态：已实现（v1.0.4）。关联文档：[按端信息卡](endpoint-info-card.md)。

## 1. 为什么重做

上一版把工具放进 Tabs，一次只能看到一个工具，且只有一个「刷新」按钮刷新全部，任一工具慢（Claude `/usage`、Codex app-server、Grok ACP 都可能耗时数秒到十几秒）就会拖住整页。反馈要点：

1. 额度样式应与「概览」一致（摘要卡片 + 明细行 + 进度条）。
2. 工具用 **card** 展示，不用 Tabs。
3. 每张 card **独立刷新**（自己的按钮 + 加载 / 失败 / 最后更新时间）；“全部刷新”可保留但次要。
4. 主进程 IPC 参数化，工具之间互不阻塞。

## 2. CPA 管理面板调研

调研对象（均为公开仓库 / 文档，只读页面结构与文案，**未复制任何代码，也不使用其接口**）：

### 2.1 CPA 额度页的信息架构

```mermaid
flowchart TB
  P[额度页 QuotaPage] --> H[页头 QuotaHeader: 标题 + 统计(凭证数 / 已加载 / 需关注) + 「刷新全部」]
  P --> T[Provider Tabs: 全部 / Claude / Codex / Antigravity / xAI / Kimi …]
  P --> G[统一卡片网格 + 分页(20/页) + 搜索 + 排序(默认 / 最快恢复优先)]
  G --> C[QuotaCard]
  C --> CH[头部: provider 图标 + 凭证显示名]
  C --> CB[主体: 由 provider 适配器渲染]
  C --> CF[脚注操作行: 刷新 / 重置额度 等 actionPill]
  CB --> PL[套餐 chip 行: 套餐等级 / 到期 / 余额 / 重置积分]
  CB --> M[窗口水位条 QuotaMeter: 5h / 7d / 模型专属 / 额外用量]
  CB --> R[重置标签: 相对倒计时 + 绝对时间, 1 小时内强调]
  C --> S[状态: idle(点击加载) / loading(骨架) / error(错误条) / success]
  P --> TL[额度时间线 QuotaTimeline: 各凭证窗口的恢复日历]
```

可借鉴的设计点（按重要性）：

| 维度       | CPA 的做法                                                                                                     | Nomi 的取舍                                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 卡片头部   | 品牌图标 + 凭证名；套餐用 chip 行（Plus / Pro / Team，高阶套餐有视觉强调）                                     | 图标 + 工具名 + **套餐徽标 + 登录方式徽标**（账号 / API Key）；Nomi 没有多凭证，所以不需要凭证名                                                        |
| 额度条     | 每个窗口一行：名称 + 已用 / 剩余 + 细轨道水位条，按占用三档着色；窗口周期 5h=滚动、168h=每周                   | 同：多窗口各占一行；**按“已用”着色**（常态 / ≥70% 黄 / ≥90% 红），沿用概览明细行的 `rows / bar` 样式                                                    |
| 重置倒计时 | 相对倒计时 + 绝对时间，临近重置强调，窗口已过期给提示                                                          | 相对倒计时（约 N 小时后重置）；窗口已过期时不显示百分比，写“窗口已重置，下次使用后更新”                                                                 |
| 状态       | 空闲 / 加载骨架 / 错误条 / 成功四态，错误信息归一化                                                            | 每卡四态：`idle / loading / ok / error` + `data-phase`，footer 用 `role=status` 播报                                                                    |
| 单卡刷新   | 卡片脚注里 pill 按钮，刷新只重取这一个凭证                                                                     | 头部右侧的「刷新」按钮，只刷新该工具；刷新中仅此按钮禁用                                                                                                |
| 批量操作   | 页头“刷新全部”；issue #347 提出三层：页级 → provider 级 → 凭证级；要求有界并发、局部失败不影响其他、可汇总失败 | 页头保留**次要**（ghost）的“全部刷新”；主进程**并行**刷新三个工具，局部失败各自落到自己的卡片                                                           |
| 加载策略   | 点击才加载（不轮询）；缓存代际 + request-id 去重，避免旧响应覆盖新响应                                         | 同样不自动轮询；同工具并发点击在主进程合并；渲染端只替换**该工具**的那一行，避免覆盖其他卡片                                                            |
| 数据来源   | 通过 OAuth 凭证调用各家 usage 接口                                                                             | **不采用**：Nomi 不读取凭据、不调用未文档化接口，只用本机已有数据 + 官方 CLI 自己取到的结果（`claude -p /usage`、`codex app-server`、Grok ACP billing） |

### 2.2 其他参考（只借鉴设计）

- **TokenTracker**：本地优先；“Usage Limits”独立视图，对本地 provider 暂时不可用时用 _last-good caching_ 显示上次值 → Nomi 的 `stale`「上次读取」徽标与“显示的是上次读到的值”。统一用量面板而非逐工具 tab。
- **OpenUsage**（macOS 菜单栏）：provider 分组的进度条；条的颜色按“燃烧速率 vs 重置时间”判定；点击在“已用 / 剩余”“倒计时 / 绝对时间”之间切换；每个 provider 可单独刷新；缓存秒开（stale-while-revalidate）；菜单栏“pin”迷你条 → 启发了按端信息卡里的**迷你进度条**。
- **vibe-usage / vibeusage**：5 小时 / 7 天订阅配额监控、悬停看“消耗 vs 时间”对比；CLI 里用 60 秒快照缓存保护上游 → 与 Nomi 现有“同一工具 60 秒内最多刷新一次”一致。
- **models.dev**：公开的模型 / 价格元数据，Nomi 已用于“价格 → 手动同步”，模型与供应商展示沿用其命名，不新增网络请求。

## 3. 最终设计

### 3.1 卡片（`UsagePanel/Quota.tsx`）

```
┌ 订阅额度 [尽力而为]                                   [↻ 全部刷新] (ghost,次要) ┐
│ ┌ Claude Code ───────────────┐ ┌ Codex ─────────────────────┐ ┌ Grok ──────┐ │
│ │ ◆ Claude Code [Max][账号登录]   [↻ 刷新] │ │ ◎ Codex [Plus][账号登录] [↻ 刷新] │ │ …           │ │
│ │ 订阅额度 · 来源：claude /usage          │ │ 订阅额度 · 来源：codex app-server │ │             │ │
│ │ 5 小时窗口   约 2 小时后重置   已用 12% │ │ 5 小时窗口   …           已用 32% │ │             │ │
│ │ ▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░         │ │ ▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░      │ │             │ │
│ │ 每周窗口     约 3 天后重置     已用 40% │ │ 每周窗口 …               已用 74% │ │             │ │
│ │ 用量与费用 · 近 7 天  Token 1.2M  $3.4   │ │ …                                │ │             │ │
│ │ ─────────────────────────────────────  │ │                                   │ │             │ │
│ │ 状态：已让官方 CLI 刷新       更新于 刚刚 │ │ 状态：加载中… / 失败：… / 更新于 …  │ │             │ │
│ └────────────────────────────────────────┘ └───────────────────────────────────┘ └─────────────┘ │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 样式复用概览：外框沿用 `.card`（摘要卡片）、窗口行沿用 `.rows / .row / .rowHead / .bar`（来源分布 / 模型排行同款），不引入新的视觉语言。
- 网格 `repeat(auto-fill, minmax(300px, 1fr))`：窄窗口自动变纵向列表。
- 每张卡片四态：`idle`（尚未点刷新）、`loading`（仅该卡按钮禁用，图标旋转，`prefers-reduced-motion` 下不旋转）、`ok`（结果说明）、`error`（认证失效 / IPC 错误，红色提示，可重试）。
- “最后更新时间”取额度数据本身的 `updatedAt`（而不是点击时间），避免“刚点过但其实没取到”造成误导。
- dsh / Nomi 对话没有订阅额度，不显示刷新按钮；API Key 登录的 Claude / Codex / Grok 仍可单卡刷新（用来重新探测登录方式）。

### 3.2 刷新 IPC（主进程）

| 通道                     | 参数                            | 行为                                                           |
| ------------------------ | ------------------------------- | -------------------------------------------------------------- |
| `ai:usage:quota-refresh` | 无                              | 全部刷新：三个工具**并行**，共享一次本机日志扫描               |
| `ai:usage:quota-refresh` | `'claude' \| 'codex' \| 'grok'` | 只刷新该工具；非法参数一律按“全部”处理（`quotaToolOf` 白名单） |

- 返回 `{ entries, tools }`；单工具时 `tools` 只含该工具的结果，`entries` 仍是完整视图，渲染端只合并该工具那一行。
- 同一工具的刷新合并（并发点击、单卡与全部同时触发都只拉起一次官方 CLI）；不同工具之间没有共享锁，互不阻塞。
- 登录状态缓存只对被刷新的工具失效（`AuthModeDetector.invalidate(id)`）。
- 沿用 60 秒节流、5 分钟“本机数据够新就不拉起 CLI”、「主动刷新额度」总开关与隐私约束（不读凭据）。

### 3.3 测试
