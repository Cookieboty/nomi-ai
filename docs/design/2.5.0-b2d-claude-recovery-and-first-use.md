# 2.5.0 B2d：Claude 冷 Unknown 显式新建与 providerless 首用 UI

状态：**受限 Claude 显式恢复决策与真实 IPC/UI 首用已接通；不是 2.5.0 完工。** 官方 Codex factory、完整 switch 事务、Windows 托管写入、API 工具对齐以及 #413–#417 均未在本切口实现或关闭。全部验收只用临时假 CLI 子进程，没有运行用户安装的 CLI、读取凭据、调用付费模型或改真实 userData。

## 1. 冷 RecoveryUnknown 后必须显式新建

`Session.ResolveUnprovenResume` 只在 phase=uncertain、`RecoveryUnknown` 且该次请求尚未 delivery 时接受。registry/IPC 要求 `confirm: true`、`decision: "new-native"` 以及请求体中存在 `expectedGeneration`；generation 不匹配为 `RUNTIME_STALE`，条件不满足为 `RUNTIME_UNRESOLVED`。

决议本身：

- 不发送、不重放、不覆盖旧 `NativeSessionID` 或 coverage。
- 取消对该 compatibility key 的 preferred binding，并把原先 Safe 的旧 binding 标为 `StatusStale`（保留身份）。
- 清除 active，generation++，会话回到 idle，下一次 Start 走 `TargetNew` / full。
- 未证明已提交的用户条目仍留在 ledger，供显式 `Retry`；它们进入 `held`，不会自动出现在后续另一条独立请求的 full 交接里。同一条未发送消息必须显式 Retry，因为 `attempted` 仍为 true。
- 取消后的 unknown、已 delivery、或非 unknown 的 uncertain 不能走这条决议，避免把可能仍在运行的进程当成可丢弃冷 resume。

idle-only `Select` 在 unknown 恢复期间继续拒绝；决议后空闲才可切换。

## 2. 真实 IPC + UI 的 providerless 首用

`wireManagedClaude` 始终安装 metadata-only probe（`LookPath`，不执行 CLI、不探测登录）。capabilities 即使未注册 factory 也会列出 Claude，并给出准确 status：`missing-executable` / `no-project` / `unsupported-platform` / `ready`。登录只允许 `unverified` | `not-advertised` | `not-applicable`，**从不广告已登录**。存在可执行文件才会出现在 `Available()` 并允许 adopt；没有 project 仍拒绝 adopt，不暗示使用主目录。API 选项仅在已注册时列出，status 为 `requires-provider`，并声明实验性纯文本、不替换旧 API 工具。

typed 合同新增 `conversations.runtimeResolve`，`conversations.runtimeCapabilities` 可带可选 `{id}` 并返回 `choices`。前端 `ManagedRuntimeDock` 接到主 Nomi 会话，经真实 `runtimeCapabilities/state/adopt/select/resolve` 与 `conversations.runtimeChanged` 工作，不是未挂接的假 store。缺失可执行文件、无项目、未验证登录和 Unknown 恢复都有可操作的说明与禁用态；Unknown 恢复必须点「新建 Claude 会话」。

## 3. 本切口保留的 B2c 行为

无 provider 前置；LookPath 不是登录；无项目拒绝 adopt；官方 argv 仍是 stream-json 合同参数；不使用 `--bare`；工具/权限保守、从不自动批准；当前请求只提交一次；ACK 只来自已校验 SID/result；取消等待进程组；Windows managed 门禁仍在 adopt 前；旧未托管 API 工具路径不改。

## 4. 验收与仍未交付

- conversationruntime：显式决议不发送、旧 binding 保留为 stale、后续 Start 是 new/full，且未证明请求不会泄漏进后一条 unique current payload。
- 真实 typed IPC + 假 CLI 子进程：缺少 expectedGeneration / 未确认 / 非 unknown 均拒绝；Unknown 后新建是 full、旧 SID 保留；决议或取消后的迟到事件不能改写权威历史。
- 生产 probe 经真实 IPC：missing-executable、no-project、unverified/not-advertised、无登录措辞；无项目不可 adopt，有项目且有假可执行文件时可 providerless adopt。
- 前端 panel 单测覆盖首用缺失可执行文件禁用 adopt、无项目说明、Unknown 必须显式新建、非空闲不可选择。

仍缺失或未在本切口开始：官方 Codex factory、完整 switch prepare/recover/handoff/commit 事务、Windows 耐久写入、API 工具/审批 UI 对齐、真机官方 CLI 验收，以及 issue #413–#417。
