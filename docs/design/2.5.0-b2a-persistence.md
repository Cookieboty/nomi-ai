# 2.5.0 B2a：convstore S1 持久化基础（fixtures 验证，默认不启用）

> 本文记录 B2a 当时的交付快照。后续实际应用调用者、实验性 API 文本路径及仍未开放的部分见 [B2b 集成记录](2.5.0-b2b-application-ingress.md)。

## 决定与实际范围

**S1 已选：扩展现有 convstore，而非另建 kernel log 再双写旧 JSONL。** 实际阅读确认，`core/shellhandlers/conversations.go` 接收视图 append/replace/put/import；`ai/runtime/airouter/chat.go` 执行 API send，两者没有一个共同事务。现有 `utils.WritePrivateFileAtomic` 只有 temp + rename，没有文件/目录 fsync 或短写检查。不能把它当作正文和 runtime 状态的耐久事务，更不能添加无原子性的 sidecar。

本阶段在同一个 Store 服务增加显式 `AdoptManaged(id)` / `OpenManaged(id)`。**生产没有调用者**；全部执行只触及测试临时目录。未改实际用户数据，没有真实 CLI、模型、登录或网络调用。

每个 opted-in 会话只有一个 `conversations/managed-v2/<id>.json` 权威提交单元：

- document version 2、单调 sequence、完整性 checksum；checkpoint version 1。
- 产品 ConversationID、所有历史 revision（stable ID / order / turn / origin / Raw）、binding identity / compatibility / coverage / invalidation、preferred binding、receipt、已尝试/完成修订、queue、active attempt / generation / phase / draft / approvals、selected target、pending switch。
- 原始 legacy index/meta/JSONL/import 字节和确定的 ID 映射也保存在同一提交单元。原始旧文件保留但不再是该会话的写入权威，不存在“写完新状态再写旧正文”的双写。
- 旧 `Store.Messages/State` 从此单元投影，未知 API 字段、大整数和附件保留；编辑后只投影最新 live revision，旧 revision 仍可审计。counts / preview 不再以旧 index 为准。

旧 append/replace/put/delete/import 对 managed ID（包括损坏的 final 文件）明确拒绝；`RewriteMetas` 不改 managed 元数据。**这不是完整应用适配**：managed rename/delete/API send 的新命令路径尚未开放，未管理的 API 会话继续走原行为。没有默默开启迁移。

## 写入原语与单写者

1. 每会话非阻塞 OS lease：同进程不同 Store / 不同进程都不能同时取得两个活 actor。一个 lease 只建立一个 Session，Close 后旧 actor 不能再次写盘。
2. 全目录短 OS operation lock 与原 Store mutex 统一串行旧 API 操作和 v2 提交；operation lock 等待而非把一次并发读取误报成永久 actor 故障。跨 Store 重载索引，避免陈旧 cache 覆盖别人的更新。
3. checkpoint 验证后做 sequence CAS；generation 不可回退；既有 audit revision 不可原地改写/删除；已有 binding 的 compatibility/native ID 不可被 clobber；既有 receipt / attempted / completed 不能回退。
4. Unix 本地文件系统：私有 temp(0600) → 检查完整写入长度 → file.Sync → Close → 同目录 Rename → directory.Sync；同时同步新建目录的父级和上级。创建、权限、写入、flush、close、rename、发布后、目录同步均有故障注入点。
5. rename 前失败仍为旧完整单元；rename 后同步失败返回 `UncertainCommit`，可见的是新完整单元但不能声称掉电耐久性。**任何保存错误都 halt actor、取消旧 context、撤销事件所有权，将内存权威退回最后成功提交并阻止后续操作**。不自动重试用户动作；必须 reopen，从校验通过的完整 old/new 单元恢复。

checksum 只检测意外损坏，**不是认证**。Commit 是内部 trusted actor sink，不是 UI 任意替换状态接口。真正的 ACK 仍须通过 Session 的 active token / generation / native ID / plan / revision / range 校验，不能因文件“有 checksum”就信任伪造的交付。

**平台边界**：Windows 锁代码可交叉编译，但 v2 写入返回 `ErrDurabilityUnsupported`，不伪装为 Unix 目录 fsync；Windows 成功路径 fixtures 明确标为不支持，有独立 fail-closed gate 测试。Linux 本轮无跳过测试。macOS 未实际运行；网络文件系统、掉电硬件、Windows 原生 runner 均未验证。生产 Windows 开启前必须补耐久替换实现与原生故障测试。

## 保存边界与重启行为

| 边界              | 先提交的状态                                                                                   | 保存失败 / 重启                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Start / StartNext | 新 user revision + attempted + preparing + queue dequeue，随后 recovered target/plan + running | dispatch checkpoint 不成功就不调用 Runtime.Start；重启不重放                                               |
| delivery          | 仅真实有效回执的 coverage + receipt + preferred                                                | submitted/recover 不算 ACK；partial 只保留真实范围并 uncertain；错误 token/native/plan/rev/span 完全不写盘 |
| text / completion | draft；完成时 assistant revision + native coverage + completed 一次提交                        | completion 写盘失败不暴露未提交的 assistant 或 coverage，保留最后耐久 draft                                |
| approval          | 保留未决状态后才调用显式 decision；结果另存                                                    | 跨崩溃不补发 allow/deny；重启撤销旧审批所有权                                                              |
| cancel            | generation fence + canceling + unknown work 先提交，再调用 Cancel                              | marker 保存失败不调用外部 Cancel；只有明确 stopped 且所有后台为空才能解锁                                  |
| edit              | 新 revision + relevant native coverage invalidation 一次提交                                   | 不复用旧摘要/范围；投影与 preview 使用新 revision                                                          |
| restart           | generation + 1 先保存再交还 actor                                                              | preparing/running/canceling/unknown、后台未静止或 pending switch 全部 uncertain；无 runtime 自动启动       |

`RestoreCheckpoint` 直接恢复修订历史，不能用 Append 把修订重置为 1。输入/输出深拷贝 Raw、capability lists、ranges、maps、queue、switch state；跨进程 lease + 持久 epoch 阻断旧 callback。持久 capability 不是一个活 Runtime；未 reattach 时 stop 只能 unknown，不能 panic 或虚构 stopped。

Pending switch 记录支持 saved-source / preparing-target / recovering-target / handoff / committing 阶段恢复，**尚未实现生产 switch 发起/提交器**。fixtures 中断任一目标准备后恢复为 uncertain；generic Cancel 不足以证明两个目标都安全，不能自动完成或回滚。旧 binding 保留。实际跨 CLI switch 的事务执行是后续工作。

## 无损迁移与失败恢复

- 同一 legacy source 的迁移确定、幂等；missing/duplicate message ID 按会话/行号/原文散列分配稳定替代 ID，不把重复 ID 当成可丢弃重复内容。
- 原始 JSONL 逐行严格检查，不调用旧“坏行跳过”的读取器。坏 JSON / 非 UTF-8 / 超大行 / 非文本 content / 非 user-assistant role / 非空 `.import` / 实际条数少于旧 index 均阻止发布，并返回问题和原始字节；绝不把不完整 staging 当成成功。
- 已有合法 v2 final 幂等返回；截断、checksum 不符、版本/修订/coverage/target 不合法的 final 显式报错，不静默回退旧 JSONL。无关 orphan temp 被忽略但不擅自删除。
- source 只读 regular file，拒绝 symlink/device/超过 64 MiB 的单个来源；32 MiB 单行限制显式阻止迁移。完整 managed 单元上限 256 MiB，超出阻止提交，不裁剪历史。超限源文件保持原地，可另行迁移；不会为了 UI 限额永久标记未交付历史。
- 附件/图片原字段及内容留在 Raw/API projection；给 CLI 的历史只允许正文，附件显式 omission，不伪装已传图片。当前有附件的用户发送仍明确拒绝（桥接未实现）。

## 验收证据

- conversationruntime：74 顶层 + 33 子测试（原 B1 70 + 19 全保留）。
- convstore：42 顶层 + 52 子测试（原 15 全保留）；包含 320 行迁移、精确未知字段/附件/大整数、重复/缺失 ID 确定映射、malformed/partial import 阻止发布、missing/malformed/stale index 重建。
- 逐 11 个 meaningful 写入边界故障；实际注入短写、ENOSPC、rename permission error；保存失败前不执行 Start / Approve / Cancel，失败 completion 不露未提交 assistant。真实测试二进制子进程持有 OS lease，发送或准备 switch 后直接退出，父进程恢复 epoch/uncertain，证明不是仅新建内存 Store 假装进程重启。
- forge ACK（错误 token/native/plan/revision/超范围）前后磁盘 checksum 不变；partial ACK 重启不变 full，编辑删除 stale coverage；fallback 重启后发 bounded full 而非旧 delta，当前 request 仅一次，原 native binding 不变。
- 上述两个包及 archguard 正常测试全绿，无 skip；`go test -race -count=3 -shuffle=on` 同范围全绿（runtime 222 顶层 + 99 子测试、convstore 126 + 156、archguard 3），`go vet` 通过。
- 既有 shellhandlers 的 conversations handlers / changed-event-source / wait-idle 三个回归，正常及 race 均通过。前端 conversationMigration / conversationStoreCache 两文件 **33/33**；changesets / repo-paths / changelog 三文件 **9/9**；generated contract **504 procedures / 95 events** 未漂移。frontend size/token、Prettier、changelog 一致性检查通过。
- 前端最初因 checkout 的 workspace 包未 build/link 无法加载（UI、catalog、SDK、voice），generated-contract 检查也曾缺少 contract dist；只在本 checkout 正常建立 workspace links、运行包 build 后，上述原测试全部通过。没 mock 模块、跳过断言、改测试配置、禁用 hook 或改共享 node_modules。
- 没有运行整仓库/GTK/真实驱动/Windows 执行测试；Windows test binary 交叉编译通过不等于执行通过。日志在 box `/workspace/dsh-runs/nomi-250-B1/b2a-{test,race}.jsonl`。
