## 1. Codex Desktop 交互清单（公开行为）

| 区域                 | Codex 怎么做                                                                                                                                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Review / Changes** | 右侧 Diff 面板；默认 Unstaged；可切 Staged / Branch / **Last turn**；头栏汇总增删；文件列表可展开行级 diff；M/A/D 状态；点文件名背景展开，点文件名可开编辑器；键盘可在文件间导航；有空态 / 加载；Last turn 仅看最近助手轮次 |

### 5.4 思考模型非流式 ~30s 客户端断连（2026-10-23）

**现象**：deepseek-v4-pro 非流式请求发出约第 30 秒被**客户端主动断开**；平台与模型服务无错。该模型默认开思考，非流式要等思考+回答全部生成完才一次性返回。

**根因**：统一网关 `apps/desktop-electron/internal/gateway/src/server.ts` 旧默认 `FIRST_BYTE_TIMEOUT_MS = 30_000` 对**流式与非流式共用**。非流式时「首字节」= 整轮生成完才出响应头，思考模型常 >30s → 网关 `AbortController` 主动 abort 上游（日志里像客户端断开）。

**影响面**（所有经网关的非流式调用，不限 DeepSeek）：

| 路径                                              | 是否流式                      | 旧风险                          |
| ------------------------------------------------- | ----------------------------- | ------------------------------- |
| Nomi 主对话 UI（`agentStream` / `stream`）        | 流式                          | 低（首字节=SSE 头，30s 通常够） |
| Nomi `sendMessage` / `agent` / 后台摘要           | 非流式 `chat()`               | 高（经网关时）                  |
| CLI harness → Claude/Codex/Gemini/Grok/dsh → 网关 | 多为流式；少数同步/探测非流式 | 非流式同高                      |
| 供应商连通性探测 `ProviderService.test`           | 非流式，15s 自有超时          | 独立，非 30s 网关               |
| TTS / ASR / MCP connect 等                        | 各有超时                      | 无关对话                        |

**修复**（`apps/desktop-electron/internal/gateway/src/timeouts.ts` + `server.ts`）：

- 流式首字节：仍默认 **30s**
- 非流式：默认 **5min**；`models[].reasoning` 时 **10min**
- 首字节总预算：流式 60s / 非流式 15min
- hooks + `NOMI_GATEWAY_*` 环境变量可配
- 单测：`tests/timeouts.test.ts`、`reliability` 非流式用例
- 设计稿 §11.1 已同步

### 5.5 发送中途断流排查（进行中）

已核对：

- **EventBatcher**（~16ms）：`flush()` 在其它 IPC 发送前调用，保证顺序；`dispose` 会 flush。非丢事件设计。
- **HarnessTabsContext**：rAF + 100ms 定时器兜底（窗口隐藏时 rAF 不跑），切 tab 前 `flushPending`。
- **partialExit**：覆盖 stop / exit1；需对照 mock 长流/工具密流回归。
- **AiChatContext AbortController**：用户中止 / 卸载时 abort，无 30s 定时器。
- 与 5.4 的 30s 网关首字节超时是**另一类**「断」：非流式思考被网关掐断，不是 EventBatcher 丢包。

仍建议：mock 长流 + 工具密流 + 切 tab/blur 的 headed 回归（可并入后续 E 用例）。

#### CLI 用量 / 压缩审计（对照环数据源与 `/compact`）

| 后端         | 流式 usage 解析（`streamParse.parseUsage`）                                                                               | Nomi 斜杠压缩                         | 备注                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- | ------------------------------- |
| Claude Code  | `usage.{input,output,cache_read_input}_tokens` + cost/duration；`status=compacting` / `compact_boundary` → status compact | `/compact` **透传**                   | 环优先实际 usage                |
| Codex        | `usage.{input,cached_input,output}_tokens`                                                                                | **不支持**（TUI-only；提示 `/clear`） | 有 usage 则环用实际值           |
| Grok         | camelCase usage 对象                                                                                                      | `/compact`、`/context` **透传**       | Nomi `/context` 卡片让位给 Grok |
| Gemini (ACP) | 视事件；无专用 compact 事件                                                                                               | **不支持**（提示 `/clear`）           | 无实际 usage 时环走估算         |
| dsh          | headless NDJSON；usage 字段经 `parseUsage`                                                                                | **不支持**（无公开 compact）          | 无实际 usage 时环走估算         |
| Nomi 对话    | 网关/本地；非 harness usage                                                                                               | **不支持**（提示 `/clear`）           | 环走 `estimateContext`          |

环逻辑：`estimateContext` 若消息上有 `HarnessUsage` 则 `basis=actual`，否则本地估算并标明「估算 · 经验表/默认窗口」。
