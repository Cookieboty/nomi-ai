# 子任务对话与主对话对齐

状态：侧栏方案。主列留在来源对话，子任务在旁边打开，两边同时更新。

## 建议

子任务必须留在右侧栏。主列一切走，就看不到父对话里的进度，也无法一边看子任务一边接着和 Nomi 说。

侧栏不再做一套缩小的输入框。它是主对话同一套管线的第二个实例，按会话 id 绑定，而不是认「当前标签」：

- 委派出去的编程助手（Claude Code、Codex、ACP）已经是 harness 标签。侧栏把 `CliConversation` 和 `MessageInput` 绑到这个 `tabId`：发送走 `sendToTab`，权限走 `replyPermissionFor`，停止走 `cancelRun`，待发列表走这份标签自己的队列。模型、权限模式、提问卡、附件、斜杠命令、转录详细程度都跟着这个 id。主列的当前标签不动，所以父对话的输入栏和流式输出照常。
- 进程内子代理（`Task`、`spawn_agent`，以及 Nomi 对话里同类的工具调用）没有自己的 harness 标签。步骤挂在父转录里、`parentId` 指向这次调用。侧栏用同一个 `ConversationView` 画出任务说明和这些步骤。没有单独的追问通道，输入栏不假装能发；能停的用 `stopAgent`。
- `delegate_to_nomi` 是后台 Nomi 任务，不是编程助手标签。侧栏用 `tasks.trace`（最近一次执行的工具步骤）和目标说明画成同一套会话。内核明确不能追问，侧栏写明要改就回主对话再派一次。进行中可以停止（`tasks.cancel`）。

不把子任务嵌进父消息列表当线程：滚动和提问卡会和父对话抢同一条时间线。也不把委派标签 `activate` 成主列：那样父对话就看不见了。

## 为什么以前会分叉

委派在 Go 里就是 harness 标签，消息、插话、权限和停止与用户自己开的标签相同。视图却只把「当前标签」交给 `CliConversation` / `MessageInput` / 提问卡 / 待发队列。侧栏打不到这条链路，就自己做了两行文本框和另一份 `subagentQueue`。

这一阶段把上述操作改成带 `tabId` 的函数，并让非当前标签的消息缓存可以被侧栏钉住（`useHarnessTabMessages`）。主列仍只订阅当前标签，不会因为侧栏里的流式输出整页重渲染。

## 能力

| 交互                       | 主对话             | 委派标签侧栏                 | 进程内子代理                                | 后台 Nomi                                  |
| -------------------------- | ------------------ | ---------------------------- | ------------------------------------------- | ------------------------------------------ |
| 消息 / 工具渲染            | `ConversationView` | 同一个 `CliConversation`     | 同一个 `ConversationView`（父转录里的步骤） | 同一个 `ConversationView`（`tasks.trace`） |
| 输入栏                     | `MessageInput`     | 同一个，绑这个标签           | 没有追问通道，不提供                        | 没有追问通道，说明原因                     |
| 插入 / 排队 / 停止         | 有                 | 有，按标签 id                | 能停则停                                    | 进行中可取消任务                           |
| 权限 / 计划审批 / 沙箱     | 有                 | 有（持续任务仍先经任务回应） | 仍出现在父会话                              | 任务自己的等待，不在这张卡                 |
| 提问卡                     | 有                 | 有，按 `tabId`               | 不单独有                                    | 不单独有                                   |
| 模型 / 思考深度 / 权限模式 | 有                 | 有，`endpointTab`            | 不适用                                      | 不适用（跟对话模型）                       |
| 附件 / 斜杠命令 / 语音     | 有                 | 有                           | 不适用                                      | 不适用                                     |
| 结果回到父对话             | 不适用             | 有，内核 follow-up 未改      | 结果留在父转录                              | 做完写回来源对话                           |
| 主列是否被切走             | —                  | 否                           | 否                                          | 否                                         |

侧栏里的斜杠命令可以发给这个标签。打开设置 / 插件的那几个按钮没有接到主窗口的面板状态。

## 会话模型

```text
SubagentTarget =
  | { kind: 'harness', tabId }
  | { kind: 'nested', callId, parentTabId }
  | { kind: 'nomi-task', taskId }
```

- `harness`：现成的标签消息、实时事件和队列。空闲时用户接着说不算接手；委派还在跑时发送仍由内核标 `takenOver`。
- `nested`：不新建存储。`callId` 在父消息的 trace 里，子步骤的 `parentId` 等于它。`parentTabId` 为空表示父转录就是当前 Nomi 对话。
- `nomi-task`：任务 id。轨迹是 `tasks.trace`（最近一次 attempt 的 jsonl，工具名和截断后的输出）。正文增量目前只在执行结束时收成 `done`，跑的过程中侧栏看到的是已经落下的工具步骤，大约每 1.5 秒拉一次。

`subagentQueue` 不再接到界面上。模块和单测还留着，确认标签队列覆盖同一组竞态后再删。

## 还没做

- 后台 Nomi 跑的过程中，模型正在写的那一段正文没有实时流，只有工具步骤和结束后的 `done`。
- 进程内子代理如果 CLI 不暴露内部步骤，侧栏只能显示任务说明和结果，和主时间线上的说明一致。
- 不能追问的两类会话没有改内核去新开一条通道。
