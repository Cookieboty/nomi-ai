# 2.5.0 B1：内存交接基础交付记录

## 范围与状态

`internal/core/conversationruntime` 是 stdlib-only 内存算法，**未接入主对话**。没有进程、凭据、模型调用、磁盘写入、UI 或真实迁移。不是完整 2.5.0，也不是可直接开放的运行时。

已实现：稳定逻辑 ID / 顺序 / 修订与墓碑；按精确 revision + digest + UTF-8 span 的每绑定覆盖；绑定兼容 key；显式 new/full 与 confirmed resume/delta；完整 prompt JSON 字节预算；typed ACK 的原子验证与幂等；编辑使已接收旧正文的原生绑定 stale；防御性拷贝；unknown 回执阻止自动续发。

后续 [B1 运行时行为切片](2.5.0-b1-runtime-behavior.md) 已实现内存 Runtime 合同、active attempt/generation、队列/审批/后台门控及 fake 端到端行为。尚未实现：公共 IPC、真实 resume 握手/结果探测、**持久** attempt/generation、崩溃恢复、rewind、官方 CLI 适配、API 写路径统一与 providerless UI。不得仅凭本包绿色声称生产安全切换事务已完成。

## 调用与计量合同

- `TargetNew` 是调用者已明确决定的新原生会话/恢复 fallback；无条件忽略传入旧 coverage，规划有界 **full**。提交必须提供新 Binding.ID、空原生 ID/coverage，首次确认学习 native ID。传入旧绑定只便于纯规划，不能覆盖旧绑定提交。
- `TargetCurrent/TargetResume` 要求兼容 key、已确认 native ID 和 safe 状态；不兼容/未知/未验证/stale 一律 blocked，**不在 Plan 内偷偷 fallback**。真实驱动 resumed/new/unknown 的判断仍未接入。
- 发送的唯一正文是 `Plan.Payload`，**不能**再另外发送 `RequestBody`。它等于历史 `Handoff + "\n" + RequestBody`，无历史时只有 RequestBody。`PayloadBytes == len(json.Marshal(Payload))`，不是分段估算；wrapper、分隔符、遗漏 marker、JSON escaping、当前请求全部在预算内。JSON 空串也占 2 字节，0/负预算明确失败。
- 这不是整个未知传输信封的预算。B2/B3 驱动必须另算 JSON-RPC envelope/argv；Windows UTF-16 文本和 always-quoted CRT argv 使用独立类型与上限，argv 总量包含空格和 NUL，不与 UTF-8 字节混加。
- 新历史按产品顺序选取完整未见 span，不因预算裁切 UTF-8 字符；partial ACK 后只补未见 span。当前请求按逻辑 ID 排除；同文本但不同 ID 的历史必须保留。普通旧失败请求重试仍保留其后产生的其他历史；只有显式 `HistoryBeforeOrder` 的新会话分支视图才排除 cutoff 之后的条目，不能隐式假装已把原生 session rewind。不明确的 turn 匹配报错，不猜。
- `Omitted` 记录所有本次未交接条目。`Reported=true` 才表示 marker 也已装入 prompt；过紧预算连 marker 都放不下时仍保留 `Reported=false` 的本地遗漏记录，不把无法容纳的诊断塞入正文。**任何 omission 都不推进 coverage**，下一次重新评估。
- 当前附件拒绝（包括已在 ledger 中但调用者忘记填 Attachments 的情况）；历史有附件的条目整体遗漏并说明原因，绝不声称其文本/附件已原生接收。图片、审批、工具现场、推理不转移。
- `DeliveredFull` 不接受混杂的 Parts；partial receipt 必须落在本计划实际发送的相同 revision/span 内，不能跨越已接收的 gap。一次回执整体原子应用；私有 plan 校验检测调用者修改 selections/payload 后再确认。回执是适配器的真实确认，**不是**文本子串猜测。
- `ConfirmNative` 用于适配器确实从同一 native session 观测到的最终 assistant 正文，避免下一次把该 session 自己生成的正文又补一遍。B1 中 Append 与确认尚非持久事务；生产必须将二者同提交，不能直接接入。
- `AttemptID` 区分相同输入的不同执行，计划 fingerprint 区分选择/兼容性/逻辑请求。后续 B1 有内存 active-attempt/generation 围栏，仍没有**持久**所有权；生产必须补齐，不能自动重放副作用。

## 从失败草稿修正的测试 oracle（没有降低功能要求）

修复前 20 个测试仅 1 通过 / 19 失败，部分失败互相级联。草稿及日志已归档在 box 的 `dsh-runs/nomi-250-B1/`，不是测试缓存问题。

1. helper 原先在 `Handoff==空 && Empty()==true` 时直接失败，反向否定了合法的无历史请求；改为检查**完整 Payload 的真实 JSON 字节与组装值**，blocked 必须没有可发送正文。
2. 原 first/fallback 测试要求新 CLI 空历史，违反 full 要求；现在模拟 Claude → Codex → Claude 的真实产品条目和显式 native 确认，新会话带 full，原绑定返回只带 delta。
3. 原 outside-planned 测试把 m2 本身也选入，再期望拒绝其合法 span；现在 m2 是明确未发送的附件条目，验证越界和整批原子拒绝。
4. 原 backfill 测试提交后仍用旧 coverage，并要求不同选择复用同一个 fingerprint；改为读取最新绑定，选择变化必须产生不同 fingerprint。
5. 当前请求属于完整 payload，其修订变化必须让旧计划失效；不能像旧断言那样成功后把旧请求记到新正文上。
6. `hello 中文 😀 "quoted"\n`（末尾是真换行）的真实 JSON 字节是 **32**，不是 26。空 JSON 字符串是 **2**，不是 0。
7. Windows 采用明确 always-quoted CRT 算法：`a b` 占 5 UTF-16 单元、`dir\` 占 7、`a\"b` 占 8（外引号、反斜杠与引号转义都算）。不是照原错误断言补常数。
