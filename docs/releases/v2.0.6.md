# Nomi·诺米 2.0.6

2.0.5 之后的修复版本，Go 版与 Electron 版同时提供（文件名以 `Nomi-Electron-` 开头的是 Electron 版）。 / A fix release after 2.0.5; Go and Electron builds ship together (Electron files are named `Nomi-Electron-…`).

## 升级到 Go 版 / Moving to the Go build

- 从 2.0.4（Electron）升级后，旧的聊天记录会出现在对话窗口里：会话列表、名称、工作区、消息都会带过来；聊天很多、新版本存储放不下时，优先导入最近更新的会话（#181） / After upgrading from 2.0.4 (Electron), your old chats appear in the chat window — list, names, workspaces and messages; if there are more than the new storage can hold, the most recently updated conversations come first (#181)
- Windows 上把资源管理器里复制的文件粘贴到对话窗口，能拿到文件路径了（#198） / On Windows, pasting files copied in Explorer into the chat now picks up their paths (#198)

## 修复 / Fixes

### 模型与网关 / Models & gateway

- Go 版里 Anthropic Messages 协议的模型能正常回复了（#187） / Anthropic Messages models reply again in the Go build (#187)
- Go 版网关在并发请求下不再可能崩溃（路由快照、会话亲和缓存、隐私脱敏、就绪等待）（#194–#196、#199、#201） / The Go gateway no longer risks crashing under concurrent requests (route snapshots, session affinity cache, privacy masking, readiness wait) (#194–#196, #199, #201)
- 价格 / 模型目录同步写入成功后才通知网关，网关不会继续用旧目录（#185） / The gateway is told about a models-catalog sync only after it is written, so it never keeps the old catalog (#185)
- MCP 工具参数类型不对时返回错误，不再让 Go 后端退出（#202） / A wrongly typed MCP tool argument returns an error instead of taking the Go backend down (#202)
- 编程助手进程提前退出时，Nomi 不再出现未捕获的错误，Codex 照常回退 / If a coding-agent process exits early, Nomi no longer hits an uncaught error and Codex falls back as before

### 对话与工作区 / Chat & workspace

- 发送准备期间切换会话，这一轮仍属于原来的会话和工作区（#184） / Switching conversation while a message is being prepared keeps that turn in its original conversation and workspace (#184)
- `workspace_run` 每次执行命令都会先确认，即使开了「自动批准」；说明里写清楚命令不受工作区限制（#186） / `workspace_run` always asks before running a command, even with auto-approve on; the wording now says commands are not confined to the workspace (#186)
- 等待确认期间你在编辑器里保存过的文件，`fs_edit` 不会再用旧内容覆盖（#190） / `fs_edit` no longer overwrites changes you saved in your editor while its confirmation was pending (#190)
- 停止生成后，迟到的「授权文件夹」卡片不会再弹出或生效（#203） / After you stop a reply, a late folder-access card no longer appears or takes effect (#203)
- 跨磁盘移动或删除到回收站的普通文件不再失败（Go 版）（#191） / Moving or trashing regular files across disks no longer fails in the Go build (#191)
- 暂存后提交（只提交已暂存的改动）在 Go 版里正常了（#197） / Committing only staged changes works in the Go build (#197)

### 角色 / Character

- 自定义角色包声明的表情映射不会被当成旧模板整表替换（#192） / A custom character pack's declared expression mapping is no longer replaced as an old template (#192)
- 构建时选的自定义角色在默认静态渲染下显示它自己的形象（#193） / A build-time custom character shows its own image with the default static renderer (#193)

### 安全与稳定 / Security & stability

- Go 版每个窗口使用单独的连接凭据，窗口身份由应用判定（#183） / Each Go window gets its own connection credential and the app decides the window's identity (#183)
- Go 版配置保存按顺序原子写入，不会被旧内容覆盖（#182） / Go config saves are atomic and ordered, so an older snapshot can't overwrite a newer one (#182)

### 安装包 / Installers

- Electron 版的知识库 OCR 与语音检测依赖能按原路径加载（#188） / OCR and voice-activity modules load correctly in the Electron build (#188)

## 说明 / Notes

- 已安装 2.0.4 或 2.0.5 的用户在应用内检查更新即可升级到 Go 版 2.0.6 / Users on 2.0.4 or 2.0.5 update in-app to the Go build 2.0.6
- 发版时 CI 会校验 tag 与版本号一致（`v${version}`），并以本文件作为 Release 说明 / On release, CI checks the tag matches the version (`v${version}`) and uses this file as the Release notes
