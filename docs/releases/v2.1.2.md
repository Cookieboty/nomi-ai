# Nomi·诺米 2.1.2

第三方供应商与稳定性修复版本：改了名的中转模型可以按已知模型处理（上下文、长上下文和计费都对得上），供应商编辑重新设计，并修复切换供应商、检测协议、用量明细等问题。Go 版与 Electron 版同时提供（文件名以 `Nomi-Electron-` 开头的是 Electron 版）。 / A third-party provider and stability release: a relay's renamed model can be treated as a known one (so context, long context and pricing line up), provider editing is redesigned, and switching providers, API detection and usage details are fixed. Go and Electron builds ship together (Electron files are named `Nomi-Electron-…`).

## 新功能 / New

- 第三方模型可以指定「按哪个已知模型处理」：中转改了名的模型（如 Aerith-opus 其实是 claude-opus），选上对应的已知模型后，上下文、输出上限、能力、长上下文和价格都按它算；自己填的数值仍然优先 / Third-party models can be "treated as" a known model: for a relay's renamed model (say Aerith-opus that is really claude-opus), pick the matching known model and context, max output, capabilities, long context and pricing follow it; values you fill in still win
- 任何模型都可以填「标准窗口」：填了就能在输入栏按标签开启长上下文，平时按标准窗口压缩 / Any model can declare a standard window: once set, long context can be turned on per tab from the input bar, and it compacts at the standard window otherwise
- Claude 系列模型声明了超过 200K 的上下文时，会给第三方中转带上长上下文所需的请求头；中转不认就自动去掉重试，之后不再带 / For Claude-family models declared above 200K, Nomi sends the header long context needs to third-party relays; if a relay rejects it, the request is retried without it and it isn't sent again

## 改进 / Improvements

- 供应商编辑重新设计：上面左边是名称和 Base URL，右边是 Key；下面左边是模型列表，点一个模型在右边看和改它的全部设置；不常用的收进「更多设置」 / Provider editing is redesigned: name and Base URL on the top left, keys on the top right; the model list below, with the selected model's settings on the right; rarely used settings fold into More settings
- 地址只填 Base URL：回车或离开输入框后自动检测，各协议的地址按检测结果填好；填的 Base URL 原样保存 / Just fill in the Base URL: Nomi detects it when you press Enter or leave the field and fills in each API address; the Base URL is kept as you typed it
- 每个 Key 的协议与限流在它自己的「设置」里；更换 Key 时按回车直接保存，弹窗不关 / Each key's API and rate limits live in its own settings; when replacing a key, press Enter to save it without closing the dialog
- 用量明细和模型质量的请求明细里，输入、输出、缓存读、缓存写分开显示 / Usage details and the model-quality request list show input, output, cache read and cache write separately
- 带搜索的下拉框（如模型选择）留出更多间距，Windows 上不再显得拥挤 / Searchable dropdowns such as the model picker have more room around the search box, so they no longer look cramped on Windows

## 修复 / Fixes

- 会话里换了供应商后，请求会发给新选的供应商，不会再被之前服务过这个会话的旧供应商抢走 / After switching a chat to another provider, requests go to the new one instead of the provider that served the chat before
- 检测供应商时，某个协议用第一个模型测不通会换别的模型再测，中转改了模型名时 Responses 等协议不再被误判为不可用；手动改了协议地址后保存会先检测，列表显示正确的协议 / Detecting a provider retries an API with other models when the first one fails, so APIs such as Responses are no longer reported unavailable on relays with renamed models; saving hand-edited API addresses detects them first so the list shows the right APIs
- Windows 上保存供应商不再卡住界面（文件被杀毒软件短暂占用时） / Saving a provider on Windows no longer freezes the window while antivirus briefly holds the file
- 委派给编程助手的任务报错失败后，自动删除它的工作副本，不再越积越多 / When a task handed to a coding assistant fails, its working copy is removed instead of piling up
- 委派任务的改动文件按所在目录区分，同名文件预览和保存不会落到另一个目录 / Files a delegated task changed are told apart by folder, so a same-named file is never previewed or saved in the wrong one
- 上游只发来空白的思考内容时，不再显示一个空的「已思考」块 / An empty "Thought" block no longer appears when the upstream sends only blank reasoning
- 关闭「用模型生成对话标题」后，第三方编程助手的新会话也不再额外请求模型起标题 / With model-generated titles turned off, new third-party coding-assistant chats no longer make an extra title request

## 安全 / Security

- 导入的供应商链接带了别的域名时会新建供应商，已有的 Key 不会被发到新域名 / A provider link that adds another domain now creates a separate provider, so existing keys are never sent to the new domain
- 用内网域名配置的本地供应商失败时只回退到其他本地供应商，不会发到云端 / A local provider configured with an intranet domain name only fails over to other local providers, never to the cloud
- 事件触发的任务在重试、续跑或退回后，仍按读过外部内容来审批写入和命令 / Event-triggered tasks keep asking before writes and commands after a retry, resume or rework, just as on the first run
