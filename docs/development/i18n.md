# 多语言开发规范

Nomi 的语言资源集中在包 **`@nomi-ai/i18n`**（[`packages/i18n`](../../packages/i18n)）；UI、Electron、看板娘和插件共享同一个词典包。`packages/ui` 与 `packages/host-electron` 只保留语言状态和宿主适配，不再各自维护语言 JSON。运行时只解析稳定 key（`project.module.message`），**中文原文不能作为 key**，也不会通过兼容映射自动转换。

## Key 和目录

稳定 key 使用三段小写 kebab-case：`project.module.message`。

| 目录                               | 用途                                               |
| ---------------------------------- | -------------------------------------------------- |
| `src/locales/zh`                   | 基准中文词典，定义完整 key 集合                    |
| `src/locales/en`                   | 英文词典                                           |
| `src/locales/<language>`           | 后续语言，目录名使用短语言标识，例如 `ja`          |
| `src/locales/<language>/<project>` | 项目边界，例如 `ui`、`electron`                    |
| `*.json`                           | 模块词典，例如 `chat-settings.json`、`common.json` |

同一个 key 必须出现在 `zh` 和所有已接入语言中。占位符也必须一致，例如 `{0}`、`{name}`。同一项目内不能让两条 key 共用同一段基准文案，避免后续维护和翻译检查产生歧义。

业务代码统一调用稳定 key：

```ts
t('ui.chat-settings.new-chat');
t('electron.common.read-failed', fileName);
```

## 修改流程

1. 在 `zh` 和所有语言的同一模块中增加或修改 key。
2. 执行 `node scripts/i18n/refresh-catalog.mjs`，更新生成的 `catalog.ts`。
3. 执行 `pnpm check:i18n`。
4. 执行相关包的 typecheck 和测试。

检查会报告：中文 key、非法 key 格式、缺失或多余翻译、占位符不一致、项目内重复基准文案、源码中的未知 key 和死 key。一次性迁移脚本 `scripts/i18n/migrate-catalog.mjs` 只用于已经完成的旧词典迁移，后续维护使用 `refresh-catalog.mjs`。

## keepZh（保留中文）

`scripts/i18n/config.cjs` 的 `keepZh` 列出**刻意保留中文、不进词典**的源文件。这些文案面向模型或内部解析，不是用户界面：

- Electron 工具 / 委派 schema（`desktop/p2tools|p3tools|tools`、`cli/delegate/*`）
- 知识库回答与日程复述片段（`knowledge/tokenize|answer`、`schedule/recurrence`）
- Agent 解析、记忆片段、沙箱与桌面 parse、遗留 TTS、唤醒词等

用户可见的 UI 字符串不要靠 keepZh 躲过检查；应写入 `packages/i18n` 并用 `t()` / `tr()`。修改 `keepZh` 时同步更新本说明。
