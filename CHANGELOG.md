New "Active quota refresh" switch in Privacy & data; API-billed tools still show "API billing, no subscription quota".

### Fixes

- **calendar:** long-running recurring events (for example a daily event that started more than 500 days ago) no longer disappear from the current calendar. The 500-occurrence safety limit now counts only occurrences returned for the queried time range, not past ones, and unbounded rules jump straight to the queried range. (`@nomi-ai/ai-chat` patch)
- **chat:** Alt+number in the Local panel now follows the visible tabs (Local, Calendar access and
- **chat:** CLI install and update progress, logs and results are kept by the main process per endpoint, so leaving the settings page or switching endpoints no longer loses them; repeated clicks reuse the running task. fix(electron): CLI probing runs asynchronously so the main process is never blocked. fix(chat): a Codex session spread over several rollout files is listed once, which removes the duplicate React key warning.
- **chat:** a Nomi message sent in the background while you are looking at a coding-agent tab (a queued message, a slash command that finishes later) is still saved to the Nomi conversation, but the sidebar no longer jumps away from the CLI conversation you are viewing. (`@nomi-ai/ai-chat` patch)
- **chat:** a streaming reply is now saved into the conversation that started it, so switching or creating a conversation mid-stream no longer leaks messages into the wrong chat. feat(chat): the send button turns into a stop button while Nomi is generating; stopping aborts the upstream request and keeps what was already generated. fix(chat): switching conversations quickly no longer lets a slower history load overwrite the visible messages.
- **chat:** deleting a conversation no longer creates a blank new one; the view switches to the most recent remaining conversation of the same kind, and deleting the last one only clears the pane.
- **chat:** deleting a conversation while its reply is streaming no longer lets the late chunks bring the deleted messages back into the view (or into the next turn's context). The in-flight stream is aborted on delete, and an empty "current conversation" is no longer treated as still active. (`@nomi-ai/ai-chat` patch)
- **chat:** drawers and dialogs (e.g. "Add provider") now start below the window title bar, so the native window buttons (macOS traffic lights, Windows / Linux window controls) always stay fully visible and the title bar stays draggable; the drawer close button is now the text "Close" ("关闭") instead of an X icon. This replaces the earlier workaround that hid or dimmed the native window buttons and intercepted window close while a drawer was open.
- **chat:** going back to the Nomi tab after opening a CLI conversation (sidebar, top tabs, shortcuts, fork) now restores the Nomi conversation, so the next Nomi turn is saved to the conversation that is on screen instead of the CLI mirror entry. Nomi turns can no longer be written into CLI mirror entries. (`@nomi-ai/ai-chat` patch)
- **chat:** in normal mode a Nomi conversation can no longer be forked to Claude Code, Codex or dsh. The context menu and the row "more" menu only offer "Fork as new chat"; cross-endpoint fork stays a dev-mode feature.
- **chat:** keep the send, microphone and headset buttons on the same row as the composer toolbar — the toolbar no longer wraps when the window is narrow or the working directory / provider / model names are long; the left-hand pickers shrink with an ellipsis and then collapse to icons (backend, working directory, model label, provider manage key) based on the toolbar width, and the plugin / provider buttons keep their size. Adds the E28 headed layout regression and a CSS-contract unit test. (`@nomi-ai/ai-chat` patch)
- **chat:** long conversations (50+ messages) no longer clip or overlap tall messages: rows are measured instead of assuming a fixed height, and are keyed by message id. fix(chat): the message list follows new content only while you are at the bottom; scrolling up to read no longer gets yanked back, and short conversations now follow the stream too.
- **chat:** results of slash commands that finish asynchronously (skill expansion, /diff, /context and the other cards, error notices) now always go back to the conversation that started them. Switching tabs while a command is running no longer sends the expanded prompt, or shows the card or error, in the other tab or the Nomi chat; if the original tab was closed or reset the result is discarded (with a notice when the conversation still exists). The input box is only cleared when you are still in the conversation that ran the command. (`@nomi-ai/ai-chat` patch, `@nomi-ai/ui` patch)
- **chat:** the result of a slash command that finishes later (a skill, /diff, /context …) started in an empty Nomi conversation is no longer delivered into a different new empty conversation; Nomi results are bound to the real conversation id instead of "new". (`@nomi-ai/ai-chat` patch)
- **chat:** the slash-command palette (and the other menus that pop up from the input box) no longer sits underneath the message text. The chat background feature gave every chat-area child `z-index: 1` while the input area had no z-index, so the whole input area — including its popups — was painted below the messages; the input area now has an explicit higher layer (`--cd-z-chat-input`) and the chat container is its own stacking context. (`@nomi-ai/ai-chat` patch, `@nomi-ai/ui` patch)
- **chat:** when two custom slash commands / skills share a name (project vs user, custom vs built-in, or a Grok bundled skill), the one that loses the bare name used to be shown as `/project:foo` but still sent `/foo`, so a different command ran. Claude Code and Grok have no verified syntax to target the other version, so those entries now stay in the menu marked "Unavailable" with the reason, and selecting or typing them shows an explanation instead of sending anything. The winner keeps the bare name, matching the CLI's own precedence. Codex (expanded by Nomi by id) and Nomi are unchanged. (`@nomi-ai/ai-chat` patch, `@nomi-ai/ui` patch)
- **chat:** while one CLI endpoint is being installed or updated, other endpoints' install/update actions are disabled and the main process refuses concurrent runs instead of surfacing a failing error task. fix(chat): CLI version info is refreshed only once after an install/update run finishes, removing a redundant round of npm version checks.
- **chat:** with knowledge-base Q&A on, a message queued while another reply is running is still answered via the cited KB path (the mode is frozen when it is queued), and regenerating / editing a KB answer keeps using KB Q&A instead of silently falling back to a plain chat. (`@nomi-ai/ai-chat` patch)
- **cli:** activating a Grok profile now also recognises a `[models]` table written as `[ models ]` or with a trailing comment, and a root-level `models.default = …`, so it no longer appends a second `[models]` table and breaks `~/.grok/config.toml`. - **cli:** permission requests from subagents running in parallel no longer replace each other. - **cli:** saving the coding-agent provider profile that is currently in use now writes the CLI config and stores the profile in a single step in the main process. ### Performance

- **ai-chat:** settings and side panels are route-split and prefetched when idle; the chat entry chunk shrinks from 643 KB to 404 KB.
- **chat:** cheaper streaming Markdown and a lighter first paint — while a reply streams, the live body is re-rendered at most every 66–320 ms (tiered by body length and CPU core count) instead of every frame, and a code block that is still open is not syntax-highlighted until it closes or the turn ends (8000-character code block at 320 chars/s: main thread 34.8% → 8.8%, 537 → 206 DOM update batches). The syntax highlighter is now a lazily loaded chunk: the chat window's entry JS drops from 901 KB to 737 KB (285 KB → 234 KB gzip). `scripts/check-bundle-budget.mjs` reports first-paint size budgets in CI without failing it. (`@nomi-ai/ai-chat` patch)
- **chat:** switching conversations is smooth again — median switch latency 252 ms → 27 ms with no long task (long Nomi conversations, 6 conversations × 400 messages). Root causes: the main process ran four synchronous `which` spawns on every harness state broadcast (now cached, never spawned when reading state), every switch waited for two redundant IPC round trips (now skipped when already on the main Nomi tab, and run in parallel with the local switch), and each Markdown block rebuilt a unified processor plus a full highlight.js language registry (now one shared lowlight instance and a settled-message render cache). A switched-to conversation paints its last messages first and fills in older ones in small batches. (`@nomi-ai/electron` patch, `@nomi-ai/ai-chat` patch)
- **harness:** a Claude Code process that has been idle for 30 minutes (configurable with `NOMI_HARNESS_IDLE_MS`, `0` turns it off) is now reclaimed to free memory — only when no turn is running, no permission request is pending, and the session can be resumed. The tab shows a hollow "dormant" dot (and a one-line hint under the conversation); the transcript and session are kept, and the next message resumes the session automatically with `--resume`. (`@nomi-ai/electron` patch, `@nomi-ai/ai-chat` patch)
