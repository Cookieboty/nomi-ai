# Automation and Desktop Capabilities

Within the boundaries you grant, Nomi can take actions on your behalf: reading and writing files, setting reminders, reading and writing the clipboard, running commands in a workspace, and executing short code snippets. Every step checks permissions, writes to the audit log, and supports undo for file edits.

Settings entry point: **Settings → Nomi → Desktop permissions**, or via the tray menu **Desktop capabilities (file grants / activity log)…**.

## Files

- **Granted folders**: Grant access through the system picker (read-only or read-write), or grant a single file. Nothing is accessible by default.
- Ask directly: "Summarize ~/Documents/report.pdf" or "Find files mentioning invoice". Nomi can list, search, read, summarize, edit, copy, and move `txt`, `md`, `pdf`, `docx`, and other files.
- **Nomi chat workspace**: Above the input box of a new chat, you can pick a workspace for each Nomi chat (new chats default to `Documents/nomi`). Files inside the workspace do not require separate grants; see [Privacy & Security](privacy-security.md#permissions-and-confirmations).
- **Asking Nomi to access a new folder**: When Nomi needs a folder outside the workspace, a **Folder access request** card appears in the chat showing the path and read/write scope: click **Grant** to allow immediately, or **Choose another folder…** to open the system picker. Paths that do not exist, are not folders, or are too broad (home directory, system directories, sensitive directories, etc.) must be picked manually.
- **Confirmation**: When approval is needed while the chat window is open, an authorization card appears above the input bar (Allow / Reject / Don't ask again for this type of action in this chat / View tool, arguments, and dry-run preview); if the chat window is closed, Nomi shows a speech bubble. Destructive actions and the first send to the cloud expand details immediately, require a 1-second delay before confirmation (to prevent misclicks), and default to reject after 120 seconds without a response.
- **Undo**: Deletions only move files to the app trash (kept for 30 days). Under **Desktop permissions → Undoable actions**, you can undo file changes made by Nomi step by step.
- **Always denied**: `.ssh`, `.gnupg`, cloud credential directories, keychains, browser profiles, `.env`, private key files (such as `id_rsa`, `*.kdbx`), and the app's own data directory are never accessible, even if inside a granted folder.
- **Protected folders**: Under **Desktop permissions → Privacy**, you can add your own protected folders (such as finance or identity documents). Just like the built-in blocklist, they remain off-limits even inside a granted folder; agents cannot work in them either and cannot read or write them inside the OS sandbox. Removing protection requires confirmation first.

## Commands

Nomi can run commands inside the chat workspace (`workspace_run`). Commands run under your user account and are **not restricted to the workspace**; whether confirmation is required depends on **Auto-review commands** and **Command allowlist**, see [Privacy & Security](privacy-security.md#permissions-and-confirmations). Clicking **Always run in this chat** on the confirmation card skips further prompts for the same command (in the same working directory) within that chat, and resets in a new chat or after restarting the app; commands that read credentials or publish are never offered this option, and it does not apply in **Ask each time** mode.

## Reminders and Clipboard

- **Reminders**: See [Scheduling and Tasks](scheduling-calendar.md).
- **Clipboard**: Nomi can read or write the current clipboard (`clipboard_read` / `clipboard_write`), asking for confirmation the first time it is used in each app run by default.

## Controlled Browser (Currently Unavailable)

Controlled browser tools (opening pages, reading pages, etc.) still appear in the tool list and **Tool permissions**, but this version has no browser integration wired up—calling them returns `"No controlled browser available in the current environment"`. To let Nomi read or interact with web pages, add the Playwright or Chrome DevTools preset under **Extensions / MCP** (see [MCP and Skills](mcp-skills.md)).

## Computer Use

Nomi can operate local desktop apps on your behalf (Finder, Notes, System Settings, etc.): it first reads the app's accessibility tree (each button and text field gets a ref ID), then clicks, types, presses shortcuts, and scrolls by ref ID. By default, it does not move the real mouse cursor or steal focus.

- **Setup**: Click **Install** under **Settings → Computer Use**; Nomi installs [agent-desktop](https://github.com/vercel-labs/agent-desktop) via npm (open source, Apache-2.0; requires Node.js 18 or newer). If the global npm directory is not writable, it can install into a user directory instead. You can **Check for updates** and update on the same page; only tested major versions are installed (currently `1.x`), and newer major versions only trigger a notification rather than auto-installing. On macOS, grant **Accessibility** permission under **System Settings → Privacy & Security → Accessibility** to the **app that launches agent-desktop**, plus **Screen Recording** for screenshots: macOS attributes both permissions to the host app—Nomi itself when called from Nomi (or the terminal running `pnpm dev` during development), so granting permission to `agent-desktop` alone is not enough. The settings page states which app to authorize, shows permission status, and opens the system guide; click **Re-check** after granting without restarting. These tools are not exposed to models until installed. Pre-installed binaries (`brew install agent-desktop`, etc.) are also detected, or you can specify the executable via `NOMI_AGENT_DESKTOP`.
- **Agents**: Once `agent-desktop` is installed (**Settings → Computer Use → Allow agents to use it**, enabled by default), newly launched ACP agent sessions such as Claude Code, Codex, and Gemini receive the `nomi-computer` MCP server and can use the same tools to operate apps (e.g., opening the app to verify UI changes after editing code). Confirmation cards identify which agent made the request, sharing the same confirmation, auditing, and blocked-app rules as chat; "Don't ask again in this chat" is tracked per agent tab. While an agent's desktop action waits for your confirmation, the Agent Board marks that tab as waiting for your action. Agents in plan mode can only read the UI (evaluated in real time from the tab's current permission mode, taking effect immediately if switched mid-session). Enabled by default (injected only when `agent-desktop` is installed); turn it off in **Settings → Computer Use** to take effect for new sessions.
- **Confirmation**: You are prompted on the first UI read and the first action. Clicking **Allow** permits this action and automatically runs subsequent desktop actions in the same chat (each agent tab counts as one chat), including payments, sending, deleting, submitting, System Settings changes, unlabeled icon-only buttons, shortcuts likely to send or quit/close windows (`Return`, `⌘↩`, `⌘Q`, `⌘W`, `Ctrl+Q`, `Ctrl+W`, etc.), and coordinate clicks that move the real cursor. Clicking **Always allow** (or turning on **Run desktop actions automatically** under **Settings → Computer Use**) applies this across all future chats without step-by-step confirmation after reading a UI, and can be turned off anytime. Before **Allow** is clicked, those sensitive actions still prompt on first use. Actions targeting password managers, banking apps, or Nomi's own windows (including coordinates landing on those windows) are always rejected and cannot be overridden; emergency stop and audit logging remain active. When **Ask each time** is selected in the input bar, every action still asks individually.
- **Post-action re-read**: After clicking, typing, pressing a key, or scrolling, Nomi automatically re-reads a short slice of the same app's UI by default so the model can confirm the result and get updated ref IDs; the model can disable this when not needed.
- **Vision fallback**: For canvases, games, remote desktops, or custom-drawn UIs where elements cannot be read, select a vision-capable model under **Settings → Computer Use**. Nomi takes a screenshot, sends it to the vision model to locate the target, gets screen coordinates, and clicks by coordinates (which moves the real mouse cursor). Every screenshot prompts for confirmation before sending; when **Only local models can read files** is on, only local vision models are allowed. Dedicated UI-grounding models such as Alibaba Cloud Bailian GUI-Plus perform better here.
- **Emergency stop**: While a desktop action is running, a **Using desktop · Stop** bar appears at the bottom of the chat window (above the chat column); when the target app is in the foreground, press the global shortcut (default `⌘⇧.` / `Ctrl+Shift+.`, customizable or disableable in **Settings → Computer Use**). The stop bar button, settings button, and shortcut all trigger the same path: canceling the active desktop action (regardless of how long it has been running), dismissing any pending desktop-action confirmation cards, and aborting the active turn (whether Nomi chat or an agent tab, including turns waiting on a confirmation card). All further desktop actions in that turn are rejected until you send the next message. The Dynamic Island does not display "operating desktop" status.
- **Isolated mode** (macOS, Apple Silicon; requires an `agent-desktop` version with the `sandbox` command—not yet in `1.2.0`, and hidden from Settings when unavailable): Selecting an `agent-desktop` sandbox in Settings runs all desktop actions inside that isolated macOS VM without touching your host desktop. Create the sandbox in a terminal first (`agent-desktop sandbox install macos`, then `agent-desktop sandbox create <name> --provider macos --set ipsw=latest`), then enable Remote Login and grant Accessibility inside the VM on first boot; Settings lets you start and stop the sandbox.
- **Blocked apps**: Password managers, keychains, banking and payment apps, and Nomi's own windows are blocked. You can add more under **Settings → Computer Use → Blocked apps** (additions only—built-in blocks cannot be relaxed; app names match by case-insensitive substring, and bundle IDs match by full segment or prefix such as `com.tencent.`). When a model targets an app by name, Nomi locates the running app and checks both name and bundle ID; if identity cannot be resolved or the app behind a name changes after reading the UI, the action is rejected. Full-screen captures (screenshots and vision fallback without a target app) are blocked whenever a blocked app has a visible window or when the window list cannot be retrieved, requiring an explicit target app instead.
- **Privacy**: UI contents are sent only to the current turn's model for that turn (cloud models cannot read them when **Only local models can read files** is enabled). You can turn on **Hide text-field contents when reading the UI** in Settings so text fields expose only character counts. Screenshots are saved locally under `userData/desktop/screenshots/` and sent to a vision model only during vision fallback (with your confirmation). Typed text is never passed as command-line arguments (including in isolated mode: if the sandbox command cannot forward `stdin`, typing fails rather than falling back to CLI arguments), and the audit log records only hashes and lengths; agent-initiated actions are tagged as `cli:<agent-name>` in the activity log.
- **Limitations**: Available only in foreground chats (background tasks cannot operate the desktop). Linux Wayland sessions support reading the UI and acting by ref ID only, not screenshots or coordinate clicks. Electron apps, games, and custom-drawn UIs may not expose accessible elements.

## Code Sandbox

Nomi can run short JavaScript or Python snippets, always showing the code in a dialog for your confirmation first. Code can read and write only its per-run temporary directory, is terminated automatically on timeout (15s default, 60s max), deletes the temporary directory afterward, and receives no API keys in its environment.

## Tool Permissions

Under **Desktop permissions → Tool permissions**, each read/write tool can be set to **Always allow**, **Ask once per run**, or **Ask every time**. Destructive tools and code execution are fixed to **Ask every time**. The permission mode in Nomi chat's input bar (Plan / Ask each time / Auto-edit files / Auto) also governs prompt frequency; see [Privacy & Security](privacy-security.md#permissions-and-confirmations).

## Activity Log

Every desktop tool invocation logs its timestamp, outcome, and arguments (storing only argument hashes and lengths), retained for the last 30 days and viewable paginated under **Desktop permissions → Activity log**. **Clear all desktop capability data** removes all folder grants, tool permission settings, and activity records.

## Implementation

- Core: `apps/desktop-go/internal/core/desktop` (grants and path checks in `path_guard.go`, confirmation in `permission_broker.go` / `consent.go`, audit in `audit_log.go`, undo in `undo_journal.go`, trash in `app_trash.go`, command review in `command_review.go`), with tool definitions in `internal/ai/runtime/igtools`.
- File parsing runs inside a restricted subprocess (`internal/core/desktop/parse`). Reading files in the workspace or granted folders does not count as external content; once a turn reads external content such as web pages, command output, or MCP responses, write actions in the same turn ask for confirmation again to prevent prompt-injected edits (you can click **Always allow** to skip further prompts in that chat).
- Code sandbox: `apps/desktop-go/internal/core/sandbox`. JavaScript uses the local Node permission model (`node --permission`, restricted to the temporary directory); Python prefers OS sandboxing (macOS `sandbox-exec` / Linux `bwrap`) and falls back to `python3 -I` when unavailable or on Windows, noting the mode in the result; see [Security Boundaries](../development/security.md#code-execution-sandbox).
- Computer Use: Executor in `apps/desktop-go/internal/core/computer` (invoking `agent-desktop` CLI, parsing JSON output, ref caching, single re-lookup by role and name after UI changes, app blocklist and sensitive-action checks in `guard.go`, install and update checks in `install.go`, settings in `settings.go`, activity tracking and emergency stop in `activity.go`, vision grounding in `vision.go`, isolated sandbox in `sandbox.go`, `computer.*` contract handlers in `register.go`), vision model calls via gateway in `internal/core/gwstore/vision.go`, emergency-stop wiring (aborting chats, dismissing confirmation cards, locking agent tabs until the next turn) in `apps/desktop-go/computer_wiring.go`, global shortcuts via `shell.GlobalShortcuts` (Wails `GlobalShortcutManager`), tools in `internal/ai/runtime/igtools/deskcomputer.go`, settings UI in `packages/ai-chat/src/components/SettingsView/ComputerSection.tsx` and `ComputerOptions.tsx`, and the chat stop bar in `packages/ai-chat/src/components/ComputerActivityBar`.
- MCP for agents: `internal/core/computer/mcpserve`. The core opens a POST-only endpoint on `127.0.0.1` (validating `Host` and rejecting browser requests with an `Origin` header). Each agent tab gets a random token written to a `0600` file under `userData/harness/computer-mcp/` (cleared on startup, invalidated when the tab closes; the OS sandbox grants read access only to that tab's own file so other tabs cannot read it). Agents launch `<Nomi executable> --computer-mcp <token-file>` as a stdio MCP server, which starts no UI and forwards stdio to the endpoint; tokens never appear in CLI arguments or agent configs. Injection is handled in `internal/core/cli/harness/computer_mcp.go` (Claude Code via `--mcp-config` with tools pre-allowed while confirmation stays in Nomi; Codex via `-c mcp_servers.nomi-computer.*`; ACP `session/new` `mcpServers`), with OS sandbox read access allowed specifically for the token directory.
- Data is stored under `userData/desktop/` (settings, audit logs, activity records, trash, and screenshots).
