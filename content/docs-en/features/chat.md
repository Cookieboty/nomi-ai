# AI Chat

![Chat window](../screenshots/chat.webp)

Open the chat window from the tray menu ("Open AI Chat"), the desktop character (when enabled), or `Ctrl/⌘+N`.

## Unified Workspace and Conversation Base

Nomi 2.5 unifies chat and coding sessions in a single sidebar:

- **Direct CLI base in main chat**: Select Nomi or any locally installed official CLI (Claude Code, Codex, Gemini CLI, etc.) per conversation right inside the main chat, and switch back to resume that CLI's native session seamlessly.
- **Agent tabs and endpoint filtering**: Pick an agent from the sidebar's **New conversation** menu (or press `Ctrl/⌘+T`) to open a dedicated agent tab; the left navigation rail lists each endpoint vertically so one click filters sessions by endpoint. See [agents](coding-agents.md).
- **On-demand side workspace**: Open the multi-tab side workspace from the title bar whenever you need side-by-side diff review, project files, split terminal, run traces, native browser, or side chat.

When creating a new Nomi chat, if an empty conversation with no messages already exists in the current workspace, Nomi switches to it instead of creating another empty one. You choose an initial endpoint from the **New conversation** menu at creation time, and main-chat conversations can switch bases directly via the model/base selector.

## Chat

- Streaming responses. On the left is the conversation list (grouped by project; see [personalization](personalization.md)), which can be collapsed or expanded with `Ctrl/⌘+B` or the button next to the title bar; when collapsed, hovering over "Chat" in the navigation rail opens the session panel as a floating overlay. Above the input bar of a new session is "Project · Branch", where you can search, switch, create, or clear a project (multi-folder projects display as "Name +N", with hover showing all folders; the branch reflects the primary folder). Once you send the first message, the project is locked in and no longer shown in the top bar. Use `Ctrl/⌘+Shift+F` to search conversations.
- `Enter` sends; `Alt/Option+Enter` or `Shift+Enter` inserts a newline. Press `↑` in an empty input box to recall your previous prompt, or type `/` to open [slash commands](slash-commands.md).
- Single-line input bar (Codex-style, with borderless buttons): the "+" menu and permission mode sit on the left, while the model selector, voice controls, and send button sit on the right. The "+" menu attaches items to the current message: images or files (same as drag-and-drop or paste), file or folder references (inserts `@` when a workspace is selected), handoff to an agent (in Nomi chats, lists installed agents and shows "Hand off to X" above the input bar, same as `/agent`), and the knowledge base Q&A toggle; agent tabs also include "Plugins / Commands". Switch models from the model button; settings live at the bottom of the left navigation rail.
- Each reply shows the model used beneath it. If you switch models mid-conversation, a note appears at the end indicating that the new model will continue with the prior context.
- **Transcript view**: The global default is under "Settings → General → Appearance → Transcript view" (initially "Thinking"). New sessions and sessions without a per-session override use this default. The menu in the title bar lets you pick a separate level for the current session, overriding the global default; each session remembers its setting across restarts (agent tabs remember by session, so closing a tab and reopening the same session from history keeps the setting; forked sessions inherit the global default). "Use global default" at the bottom of the menu clears the per-session override. Applies to both Nomi chats and agent tabs:
  - **Normal**: Tool calls between two replies fold into one summary line per kind (Explore / Command / Edit / Other; items of the same kind do not have to be adjacent, at most one line per kind per segment, ordered by first appearance), e.g., "Explored 3 files, 2 searches", "Ran 2 commands", "Edited 1 file +12 −3". An active category shows the step currently running (e.g., "Running command pnpm test"), and failure counts appear on the corresponding line. Click to expand individual steps, and click a step to view arguments and output. Thinking is not shown separately (if a segment only has thinking, a single "Thought" line is shown). Subtask cards, mid-turn injected messages, and generated images still appear individually.
  - **Thinking**: Tool calls still fold into one line per kind; thinking blocks between two replies are combined into a separate block (expanded while running, collapsed when done, with duration counting only thinking time).
  - **Verbose**: Every tool call appears on its own line without folding; arguments, output, thinking content, and subagents are expanded by default.
  - When collapsed, the thinking line displays "Thought for N seconds" plus the first sentence of the thinking block; while running, it displays "Thinking" and the sentence currently in progress. Active thinking and tool steps show a flowing gray gradient shimmer across the text (static when the system "Reduce motion" setting is enabled).
- When the knowledge base or long-term memory is used, replies show citations and how many memories were referenced.
- When a conversation nears capacity (~95%), earlier messages are automatically compacted into a summary before sending, or you can run `/compact` manually with an optional focus (e.g., `/compact focus on the API design`). Capacity is judged from actual context usage in the previous turn rather than estimation alone. The summary is organized into sections ("Requirements, Decisions, Files & Code, Errors & Fixes, Results, To-dos, Current Work"), followed by recently read or edited files, the latest plan, and used skills; long-term memories already supplied to the model before compaction are preserved alongside it.
- When actual usage in the previous turn exceeds ~60%, large outputs in tool records older than the last 3 turns are trimmed to keep only their beginning and end, allowing raw conversation text to stay intact longer before compaction is needed. The trimmed boundary only advances when usage exceeds the threshold again, keeping the prefix sent on each turn unchanged so prompt caching is not broken.
- During multi-step tool loops in a turn (reading files, running commands), each step checks actual usage: when approaching capacity, earlier large tool outputs keep only their beginning and end, and Nomi re-reads them if needed; if still near capacity, earlier steps in the current turn are compacted into a summary before continuing; if the model still reports a context-length error, Nomi compacts further and retries that step once instead of failing immediately. Background Nomi tasks follow the same behavior.
- Command and code outputs exceeding the cap (30,000 characters for commands) preserve the beginning and end while eliding the middle, ensuring errors and failing test cases are not truncated away. When any tool output exceeds 30,000 characters, Nomi first inspects the head and tail and reads the middle in pages if needed (kept only for the active run and inaccessible from other chats; read content remains subject to "Only local models can read files").
- Saying "done" does not mean the turn is done: if the current turn's plan (`plan_update`) still has unfinished steps, Nomi is prompted to continue or mark unachievable steps as skipped with a reason, up to two reminders per turn; if nothing is done after a reminder, prompting stops. During automatic continuation, if a turn only edits the plan or repeats identical calls, it stops instead of spinning.
- Thinking content from previous turns is not re-sent with history (protocols other than Anthropic count it toward input tokens). On-demand tools stay enabled for the rest of the conversation once activated, and the system prompt does not vary by topic, preserving prefix caching. Execution traces and `/context` display the cache hit rate from the previous turn.
- Like Codex, tool calls and results from previous turns (read files, command outputs) are passed into the next turn verbatim rather than as reply text alone; previously sent content is re-sent verbatim each turn to work with provider prompt caching (Anthropic cache breakpoints, OpenAI `prompt_cache_key`), so follow-up turns mostly hit cache.
- From a conversation row's menu, you can rename, delete, or "Fork…"; each reply also has a "Fork from here" action that keeps history only up to that reply. `Ctrl/⌘+Shift+F` directly forks the current conversation into a new one.

## Where Conversations Are Stored

Conversations (entries for Nomi chats and agent tabs in the sidebar) are stored by the core in `userData/conversations/`:

| File                  | Contents                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------- |
| `index.json`          | Conversation list (name, endpoint, workspace, updated time, etc.), message counts, active ID  |
| `previews.json`       | First 300 characters of each conversation's first user message (for sidebar search)           |
| `migrated.json`       | Marker indicating legacy `localStorage` data has been imported (also recorded in `index.json`) |
| `messages/<id>.jsonl` | One message per line                                                                          |

- New messages are appended to the end of the `.jsonl` file; edit-and-resend, clear, fork, and exceeding the maximum retained message count rewrite the whole file. Full rewrites and index updates write to a temporary file first and then rename atomically with `0600` file permissions.
- The chat window keeps messages in memory only for the dozen or so most recently opened conversations (plus the active conversation and any not yet persisted to the core); others are loaded from the core when opened.
- Writes: the UI updates first, and writes are queued sequentially to the core (one at a time; as soon as one returns, the next is sent without batching). If a write fails temporarily (disconnected socket, disk error), it backs off and retries a few times; if it still fails, it stays in the queue without data loss and retries after ~15 seconds or on the next write, showing a one-time "Conversation history could not be saved right now" notice. If the core reports the conversation missing (failed to create or index rebuilt), it recreates the conversation from the UI's title and full message list and continues writing; retried appends perform a full rewrite to avoid duplicates. Writes rejected by the core for invalid arguments are not retried and show the same notice.
- On exit (tray, `⌘Q`, log out), the core waits for queued chat window writes to finish before closing: up to 1.5 seconds, exiting immediately once 200 ms have passed with no pending writes. The remaining risk window is a message generated in the last few milliseconds before exit that has not yet reached the core, or a write still waiting in retry.
- If `index.json` is corrupted (invalid JSON), it is moved to `index.json.corrupt` (with a timestamp added if one already exists, never overwriting), and the conversation list is rebuilt from `messages/*.jsonl` (name taken from the first user message, timestamp from the message, marked `recovered`; empty conversations are not recovered and the active conversation pointer is lost). The same rebuild runs if `index.json` is missing while message files exist. Migration status relies on `migrated.json`, so a rebuild will not re-import from legacy `localStorage`. If `index.json` cannot be read (permissions or I/O error), it is not treated as empty: all reads and writes fail, and the chat window shows "Conversation history is temporarily unreadable" with a "Retry" button instead of showing an empty list or triggering migration.
- On startup, a boot screen prevents a blank window: it fetches the conversation list (5-second timeout per attempt, up to 3 retries) and shows progress during the initial legacy conversation import.
- In 2.2.0 and earlier, conversations lived in the chat window's `localStorage` (~5 MB WebKit quota, which failed when full). On first launch of 2.3.0, those conversations (plus old chats extracted from the 2.0.4 Electron version) are imported into the core in parallel, verified by count, and marked complete; unfinished imports resume on the next launch without overwriting existing conversations. Conversation IDs follow the same rule as the core (letters, digits, `_`, `-`, excluding Windows reserved names such as `con`, `nul`, `com1`, validated by `isValidConversationId` in the contract); invalid legacy IDs are mapped to deterministic new IDs (`m_<hash>_<usable_suffix>`) with the original ID recorded in metadata `legacyId`. Legacy `localStorage` keys are kept for one release so downgrading back to 2.2.0 still shows conversations from that point (newer messages are not included).
- "Export data" in Settings packages all of `userData/conversations/` into `conversations/` inside a zip archive (`conversations.json` contains only chat preferences). There is no in-app restore from export archives; exports are for inspection or personal backup.

## Images and Files

- **Paste** or **drag and drop** images into the input box: up to 4 per message, max 20 MB each (PNG / JPEG / WebP / GIF / BMP), automatically compressed before sending. Conversation history saves only thumbnails; originals are not written to disk.
- Requires a vision-capable model; local vision models (such as Ollama's `qwen2.5vl` or `llava`) work too. When "Only local models can read files" is enabled, images are not sent to cloud models; cloud models ask for your consent before receiving an image for the first time.
- Up to 10 other files can be attached: text files up to 200 KB are sent with their contents, while larger or binary files pass only their local path for the model to read with tools.

## Image Generation and Asset Library

Assign an image generation model to Nomi under "Settings → Models & Agents → Task & Cost Routing" (defaults to "Auto", picking the image model from the same provider as the chat model), then ask Nomi to generate images directly. Generated images and images produced by agents go into the sidebar's **Asset Library**:

- Filter by category (Illustration / Character / Landscape / Animal / Other), source, and search (prompt, filename, tags). The top-right corner shows used storage (actual size of all images).
- Auto-categorized after generation: first matched by prompt keywords, then classified by the auxiliary model (the same model used for command review; falls back to keywords only if unconfigured or if the model is in the cloud without your consent). Older images are categorized by keywords.
- In the masonry grid, metadata stays on the card: category in the top-left, source and resolution along the bottom; click to inspect the prompt in the detail view.
- Click an image to open the detail view: full-screen preview, actual resolution in the top-left, copy image, and under "More": download, reveal in folder, or delete (moves to system trash). Navigate left/right or via the bottom thumbnail strip. The right pane shows filename, prompt, editable tags, editable category, asset info, and related images in the same category; you can also edit from this image, use it as a reference image, or regenerate (which calls the image model again).
- The Asset Library does not include uploads: it only stores generated images. Original images you send in chat are stored in the local chat directory (`userData/chat/images/user-…`) and can be viewed, downloaded, or used with "Edit / Use as reference" from the message bubble, without appearing in the Asset Library list.

Transient image service failures (network, timeout, rate limit, server error) automatically retry twice; if the image was already generated and only downloading failed, only the download is retried without regenerating. Auth and parameter errors are not retried.

## Handing Off to Agents (Delegation)

Nomi can hand off specific coding, documentation, review, and research tasks to local agents. **Tasks run in the background by default**: once dispatched, you can keep chatting with Nomi, and results return to the conversation when finished.

- Ask naturally, e.g., "Have Codex fix the login bug", or use `/agent codex fix the login bug` to specify the agent. The command dispatches immediately, passing along any attached images' Asset Library paths; requests over 4,000 characters are not dispatched and prompt you to shorten them first. You can click Stop while waiting for confirmation. If dispatch fails (not installed, delegation disabled, no workspace selected, user declined, or stopped), the chat states the reason directly instead of letting the chat model reply as if the handoff succeeded. Typing `/agent codex` alone queues it for your next message (shown above the input bar; click to cancel).
- Before dispatching, confirmation follows Nomi's permission mode ("Plan" mode never dispatches). When a workspace is selected for the conversation, the agent starts in that workspace (or a subdirectory inside it).
- Delegated agents run at the highest permission level the target agent supports ("Full access" for agents that support it, or "Ask each time" for others such as MiniMax), independent of Nomi's current mode or the "Auto-approve everything" toggle; the pre-approval confirmation card explicitly displays the effective permission level and applicable host protections.
- Each subtask opens as a background agent tab using that agent's default source for new tabs (official account or third-party provider). The subtask card in chat shows progress, subagents, and pending approvals, and can be stopped individually. When finished, the result appears in the conversation along with modified files and generated images (same for image generation tasks delegated to background Nomi), which Nomi can read on the next turn. Background Nomi writes results in the language you used to assign the task (English prompts produce English results).
- Click "View" on a subtask card to open the subtask in a side panel next to the chat while the main conversation stays in place and both update live. The side panel uses the same message list, input bar, prompt cards, and queued-message controls as the main chat (model, permissions, attachments, and slash commands belong to the subtask's own tab rather than competing with the main thread). Sending while running injects a message (if unsupported, waits until the current turn finishes), "Stop" interrupts the turn, and sending while idle starts another turn. Results from subsequent turns also flow back into the main chat. Press `Esc` or click Close to leave the side panel without switching away from the main thread. Subagents inside an agent (`Task` / `spawn_agent`) and tasks delegated to background Nomi can also open in the same side panel: if steps are available, they render with the same message view; if there is no separate follow-up channel, the reason is shown, and stoppable tasks can be stopped. See [Subagent Chat Parity](../design/subagent-chat-parity.md) for the design.
- The "Session details" button to the left of the file panel toggle in the title bar (visible once messages exist) opens a column on the right side of the chat card (without covering messages; the chat area narrows accordingly with padding around it; click again or press `Esc` to collapse, and its toggle state is remembered). It shows the workspace name and current branch at the top (hover for full path); "Changes" shows the number of modified files and added/removed lines for this session and opens the diff view (when there are no changes, it displays "No changes yet" and is not clickable); "Agents" lists subtasks and subagents used in this session with their statuses (Running / Waiting for you / Done / Failed / Stopped), clicking a subtask opens it in the subtask side panel; "Tasks" lists persistent tasks created from this session and their statuses (including tasks handed to background Nomi, such as "Generate a set of images"; agent subtasks appear under "Agents" without duplication), clicking opens the Tasks page. Both lists show 5 items initially with "…" to expand the rest; empty sections are hidden. Opening the middle diff or file preview pane automatically collapses this column regardless of window width; when the window width is under 1440 px, opening the file panel or subtask side panel also collapses it to leave room for the chat; on wider screens, it stays open when the file panel or subtask side panel opens, switching to an overlay anchored at the top-right of the chat column without squeezing messages (clicking outside does not dismiss it; click the button again or press `Esc` to close). After an auto-collapse, clicking the button reopens it as an overlay at the top-right of the chat column (even with the middle pane open, it sits over the chat rather than covering the diff or file preview) without squeezing the chat; clicking outside the overlay or pressing `Esc` dismisses it, and changing those pane toggles restores the automatic rules.
- Approvals on delegated tabs wait up to 10 minutes (2 minutes on tabs you open yourself).
- When finished, the agent reports in a fixed structure: what was done, which files were changed, what remains unfinished, and what needs your decision.
- Settings: "Settings → Nomi → Permissions & Handoff" contains the master toggle and default assignments by task type (Coding, Specs & Docs, Code Review, Research); choosing "Let Nomi choose" picks from installed agents.
- **No agent installed, or delegation disabled**: Nomi stops proposing handoffs and handles the work directly using file tools to read code, `fs_edit` for incremental edits, and `workspace_run` to build and run tests (requires selecting a workspace for the conversation).

## Long-Running Tasks

- For multi-step work, Nomi first outlines a checklist via `plan_update` (steps with In Progress / Done) and updates it as each step finishes so progress stays visible in chat.
- A single turn allows up to 20 consecutive tool calls; if Nomi still needs more tool calls when the limit is reached, it **continues automatically for another turn** without you typing "continue", up to 20 automatic continuations regardless of token usage. Auto-continuation stops if you rejected a step during that turn. When stopped, the end of the reply explains why, and saying "continue" resumes from there. You can click Stop at any time.
- On continuation turns, large tool outputs from earlier in the turn (read files, test logs) keep only their opening section to avoid filling context; Nomi re-reads them if needed.
- Tools are supplied on demand so unused ones do not occupy context: file-viewing tools are always present when a workspace is selected; file-writing tools (create, modify, move, delete) appear when the conversation discusses making changes; delegation tools for agents or background Nomi appear when discussing coding tasks, extended work (documents, reports, image sets, background jobs), or progress checks, along with the rules for doing it directly vs. handing off. Once provided, they stay available to preserve prompt caching.
- File reads default to 4,000 characters per call and searches default to 20 results; Nomi reads further or increases the limit when needed.
- When uncertain, Nomi asks you above the input bar (`ask_user`): one card at a time, lettered options, custom input on the last row, and optional multi-select. Press `Enter` to continue (advances to the next question if any) or `Esc` to skip the card with an optional note below. Answering, skipping, clicking Stop, emergency stop, closing the session, or waiting 10 minutes without a reply resumes or ends the turn; on skip or timeout, Nomi proceeds with the safest approach and states its assumptions. Questions from Claude Code, Codex (app-server questions and form-style MCP elicitation), and ACP (`elicitation/create` forms) use the same card. Tool allow/deny prompts for commands, file edits, and ACP still use their dedicated cards. When Codex falls back to `exec`, there is no interactive channel for questions.

## Sidebar

The bottom of the sidebar holds app-level entries: Settings, "Knowledge · Memory · Schedule" (`Ctrl/⌘+Shift+M`, right drawer), and "Extensions / MCP" (`Ctrl/⌘+Shift+E`). When a new version finishes downloading, "Restart to update" appears on the right side of the title bar (to the left of the Transcript view button), or at the bottom of the Settings navigation while on the Settings page. Above the conversation list are "Tasks" (see [Scheduling and Tasks](scheduling-calendar.md#tasks)) and "Asset Library". Main window position and size are remembered.

## Implementation

- UI: `packages/ai-chat/src` (`App.tsx` handles assembly only; state lives in `app/`: panel toggles, commands and shortcuts, slash commands, right column; plus `components/Sidebar`, `components/MessageInput`, `components/AssetLibrary`).
- Conversation storage: Core in `apps/desktop-go/internal/core/convstore` (contract `conversations.*`, handlers in `internal/core/shellhandlers/conversations.go`); UI in `packages/ai-chat/src/services/conversationStore.ts` (sync facade + message cache + ordered write queue), `conversationBoot.ts` (startup index fetch and migration), `conversationMigration.ts` (legacy `localStorage` import), `components/BootScreen` (boot screen); shutdown write drain in `shellhandlers.ConversationWrites` (`OnShutdown` in `main.go`).
- Cross-turn context: The core emits `steps` blocks at the end of a turn (messages actually sent during that turn's tool loop, `internal/ai/runtime/aisdk/provider.go`), which the UI stores on the reply's `steps` and passes back verbatim on the next turn (`services/history.ts`); newly recalled memories are stored on the user message's `memory` field and prepended before the user text rather than placed in `system`; on compaction, they are merged into the compacted message (`services/compaction.ts`).
- Core: `apps/desktop-go/internal/aichat` (extraction of 2.0.4 Electron legacy chats), image generation in `internal/ai/runtime/igtools/image.go`, Asset Library in `internal/core/chatassets`, delegation in `internal/core/cli/harness`.

## File Sidebar and Focused Reading

Bare URLs and Markdown hyperlinks in both user and assistant messages are clickable. Web links open in the default browser; local Markdown, text, and code links open in a standalone file sidebar with line-range navigation and highlighting via `file:30-40` or `file#L30-L40`. Code fences, inline code, and plain bare file paths remain unchanged.

The sidebar supports multiple file tabs, table-of-contents and section jumping, in-file search, and toggling between rendered Markdown and source. Editable files auto-save; external modification conflicts or save failures preserve the draft and show a notice. Selecting text with the mouse opens an action menu (also accessible via right-click): Copy, or "Ask Assistant", which adds the filename and line range as a reference chip in the input box—clicking the chip jumps back to the file, and it can be removed before sending. The selection menu does not steal focus and dismisses as soon as you start typing.

Drag the divider to resize the sidebar; expanding it enters focused reading mode. The original chat and input box collapse into a circular Nomi button in the bottom-right corner without obscuring the document. Clicking the button or choosing "Ask Assistant" from the selection menu expands a draggable floating chat window, which can collapse back into the button from its top-right corner or by clicking the document when the input box is empty. Drafts and background replies are preserved; you can choose any conversation in the same workspace or create a fork that inherits the source's settings. If the document's source mismatches the target conversation, a warning helps prevent sending to the wrong thread.

`Ctrl/⌘+F` searches the current file, `Ctrl/⌘+Shift+F` searches conversations, and `Ctrl/⌘+Shift+T` creates a conversation fork. `Esc` dismisses layers progressively: first closing any open menu or search bar, then collapsing conversation content and shrinking the floating window back to a button, and finally exiting fullscreen and closing the preview.

Markdown rendering for chat messages and files is maintained separately, and both support Mermaid diagrams. Images open in a dedicated viewer; HTML, PDF, Office, CSV, audio, and video files open with the system default application, while local file access still passes through the core's path and authorization checks.
