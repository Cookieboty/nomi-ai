# Auto-Update

Settings entry point: **Settings → About** (also reachable from the version card at the top of **General**). The page contains only the version card—check for updates, project homepage / changelog / recent updates / feedback—with **Update settings** in a secondary dialog (automatic checks and showing release notes after updating); the GitHub Star prompt at the bottom can be dismissed.

- Installed builds check for updates roughly 15 seconds after launch and every 3 hours thereafter. You can disable **Check for updates on launch and periodically** in **Update settings**, or click **Check for updates** manually anytime.
- When a new version is found, Nomi downloads the installer for your platform in the background and shows progress in Settings. If a release was just published and your platform's installer has not finished uploading yet, Nomi prompts you to check again later.
- Once downloaded, Nomi displays "Update downloaded, restart to install", shows **Restart to update** at the right of the title bar (when outside Settings) and bottom-left of Settings, and **Restart and install** on the **About** page (with a confirmation dialog). **Your confirmation is always required** before installing—Nomi never installs updates silently on quit. After you confirm:
  - **macOS**: Nomi exits, swaps the new version into its existing location (`Nomi.app` in Applications), and relaunches automatically without requiring drag-and-drop. Only when Nomi is not in a writable location (e.g., running directly from a `.dmg`, running quarantined from Downloads, or inside a non-writable folder) does it open the new `.dmg` for you to drag into Applications.
  - **Windows**: Runs the installer silently in the background to overwrite the installation and relaunches automatically without showing a wizard.
  - **Linux**: AppImage replaces itself in place and relaunches; `.deb` packages hand off to the system software installer.
- Checks or downloads with no response for 90 seconds cancel automatically and report a failure; failures at any step specify which step failed and change the button to **Retry**.
- On relaunch after updating, if **Show release notes after update** is enabled (on by default), Nomi displays the release notes for the new version; you can reopen them anytime from **About → Recent updates**.
- Auto-update is disabled when running from source, and Settings notes this.
- After an update finishes installing and relaunches, Nomi deletes used installers from the cache directory (`dmg`, `zip`, `exe`, `AppImage`, `deb`) along with incomplete partial downloads. Installers for versions not yet installed are kept to avoid re-downloading. Nomi never deletes the currently running binary, files in your Downloads folder, or any user data: the macOS `.zip` used for in-place replacement is deleted right after successful extraction, while Windows installers and system-opened `.dmg` / `.deb` files wait until the new version launches because the installation process still needs them.

## Implementation

- Update feed: `latest-go.json` on this project's GitHub Releases (per-platform installer URL, size, SHA-256, and release notes; macOS entries also include an `update` field pointing to the `-mac.zip` used for in-place replacement); downloads are verified by SHA-256.
- macOS in-place swap (`swap_unix.go`): Extracts the `.zip` into a hidden staging directory next to `Nomi.app`, verifies a valid signature, matching Bundle ID, and matching Team ID with the running app, then uses a small standalone helper script to wait for Nomi to exit, swap the new `Nomi.app` into place (restoring the old one on failure), and relaunch it.
- Windows runs the NSIS installer with `/S --updated --force-run` (`packaging/windows/installer.nsi`).
- Code: `apps/desktop-go/internal/core/updates` (`service.go` for scheduling and state, `github.go` for download and install, `releasenotes.go` for release notes); the manifest is generated by `apps/desktop-go/packaging/update-manifest.py`. See [Release Process](../RELEASE.md).
